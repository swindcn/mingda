# 熔炼执行与多次转运设计

更新时间：2026-08-14

## 目标

在现有生产工单、合炉排产和熔炼执行闭环上增加现场防错与炉包追溯：开始生产时确认实际熔炉，熔炼后允许分多次绑定浇注包或球化包并记录重量，最终完成数据回写关联生产工单。管理端与小程序端使用同一后端状态机，小程序保留扫码能力。

## 排产页面布局

- `melt-scheduling-layout` 的比例按扣除左侧导航栏后的内容区计算。
- 桌面宽屏目标比例为待排产工单 `75%`、排产凑吨计算器 `25%`。
- CSS 使用 `grid-template-columns: minmax(0, 3fr) minmax(400px, 1fr)`，右侧计算器最小宽度为 `400px`。
- 右侧六个主要字段按两列、三行展示：熔炼车间、目标熔炉、选用配方、执行班组、计划开始、预计完成。
- 待排产列表压缩选择、剩余件数、剩余铁水、交期、优先级和分配件数等固定信息列；用户可继续拖动表格列宽。
- 当内容区不足以容纳左右两栏时切换为上下排列，不能通过压缩文字造成遮挡。

## 设备主档

设备配置新增“设备类型”字段，选项来自字典 `equipmentTypes`：

- 熔炼炉
- 浇注包
- 球化包
- 其他设备

历史设备迁移时默认设为“熔炼炉”，保证现有配方和排产关系继续可用。新增设备必须选择设备类型。熔炼配方的适用设备仅允许选择启用的“熔炼炉”；转运操作仅允许选择启用的“浇注包”或“球化包”。

一期不校验浇注包或球化包容量，因为同一炉次允许多次转运。设备编码作为二维码内容和扫码匹配主键。

## 炉次状态机

```text
WAITING（待生产）
  -> IN_PROGRESS（熔炼中）
  -> TRANSFERRING（转运中）
  -> COMPLETED（已完成）

WAITING -> CANCELED（已撤销）
```

- 只有待生产炉次可以开始或撤销。
- 只有熔炼中炉次可以提交第一次转运。
- 第一次转运后状态进入转运中；转运中允许继续追加任意次数转运记录。
- 只有至少存在一条转运记录的转运中炉次可以完成。
- 已完成和已撤销炉次不能再开始、转运或完成。
- 所有状态变更使用 `versionNo` 乐观锁和数据库事务。

## 计划熔炉与实际熔炉

现有排产选择的炉子继续作为计划熔炉，不覆盖历史排程。炉次新增实际熔炉关系和快照。

开始生产弹窗默认选中计划熔炉：

- 选择与计划一致时直接开始。
- 选择不一致时二次确认“计划熔炉为 A，是否改用 B 开始生产”。确认后写入实际熔炉，不修改原计划熔炉。
- 可选实际熔炉必须启用、设备类型为熔炼炉、属于炉次车间、适用于炉次生效配方，并满足单炉容量要求。
- 若所选实际熔炉已有其他熔炼中或转运中的炉次，禁止开始，避免现场一炉多任务。

管理端只提供下拉选择，不提供扫码。小程序同时提供下拉选择与 `wx.scanCode`；扫码结果按设备编码匹配，无法匹配或不符合条件时给出明确错误。

## 多次转运记录

新增独立 `HeatOrderTransfer` 数据结构，每次转运保存：

- 关联炉次。
- 浇注包或球化包设备外键、编码快照、名称快照、类型快照。
- 本次转运重量，单位 kg，当前必填且大于 0。
- 重量来源：一期固定 `MANUAL`，未来数采写入 `DEVICE`。
- 操作人、操作时间、备注。

同一炉次允许多次使用同一包或不同包。转运累计重量为所有有效转运记录重量之和，不对目标重量和包容量做强校验；超过目标重量时仅在界面显示差异提示。

管理端转运弹窗提供包设备下拉、转运重量和备注。小程序提供包设备下拉、扫码、转运重量和备注。

## 完成重量与生产工单联动

- 完成弹窗的实际出炉重量默认等于转运记录累计重量，用户允许修改。
- 最终提交的实际出炉重量是权威完成重量，转运累计仅作为过程数据和默认值。
- 最终重量继续按各生产工单的计划铁水重量比例，写入 `HeatOrderAllocation.actualWeightKg`。
- 生产工单的 `meltCompletedQuantity` 只累计状态为已完成炉次的分配件数；熔炼中和转运中不计入完成件数。
- 生产工单增加或返回 `meltCompletedWeightKg`，累计已完成炉次分配后的实际重量。
- 工单详情的关联熔炼任务列表实时展示：炉次状态、计划熔炉、实际熔炉、转运累计重量、最终重量、开始人/时间、最近转运人/时间、完成人/时间。
- 关联炉次每次状态变更后从后端重新查询，不在前端本地推算状态。

## 执行记录与权限

炉次记录增加 `TRANSFERRED` 动作；开始记录保存计划与实际熔炉，转运记录保存包设备和重量，完成记录保存转运累计与最终重量。

权限新增：

- 管理端：`production.heat.transfer`。
- 小程序：`mini.production.heat.transfer`。

开始、转运和完成继续分别校验 `start/transfer/complete` 权限。小程序还必须满足执行班组成员关系。管理端和小程序权限键不可混用。

## API 设计

- `GET /admin/production/heat-orders/:id/execution-options`
- `GET /mini/production/heat-orders/:id/execution-options`
  - 返回符合条件的熔炼炉和可用包设备。
- `POST .../heat-orders/:id/start`
  - 参数：`versionNo`、`actualFurnaceCode`、`confirmFurnaceChange`。
- `POST .../heat-orders/:id/transfer`
  - 参数：`versionNo`、`packageEquipmentCode`、`weightKg`、`weightSource`、`remark`。
- `POST .../heat-orders/:id/complete`
  - 参数保持 `versionNo`、`actualOutputWeightKg`、`remark`。

统一返回最新炉次 DTO，包含 `transfers`、`transferTotalWeightKg`、实际熔炉和操作权限字段。

## 前端与小程序展示

- 管理端熔炼列表增加“转运中”状态筛选和状态标签。
- 管理端列表与详情中的动作按状态显示：待生产显示开始，熔炼中/转运中显示转运，转运中显示完成。
- 小程序熔炼列表增加“转运中”页签。
- 小程序详情固定底部动作按后端 `canStart/canTransfer/canComplete` 控制。
- 小程序列表和详情中的“计划出炉时间”统一改为“计划开始时间”，读取 `plannedStartAt`。
- 时间线显示任务下发、开始生产、每次转运和完成生产，包含操作人和操作时间。

## 异常处理

- 实际熔炉不符合设备类型、车间、配方、容量或占用规则时返回明确 400/409。
- 设备二维码不存在或设备类型错误时不允许提交。
- 状态或 `versionNo` 已变化时返回 409，并提示刷新任务。
- 完成时没有转运记录、最终重量小于等于 0 时返回 400。
- 所有后端事务失败时不产生半条转运记录或部分工单重量分摊。

## 测试范围

- 数据迁移后历史设备类型和历史炉次可正常读取。
- 开始时选择计划熔炉直接成功；改用兼容熔炉需确认；不兼容或占用熔炉被拒绝。
- 管理端和小程序端权限隔离，非班组成员不能操作小程序任务。
- 第一次转运进入转运中，多次转运均保留，累计重量正确。
- 完成默认值等于转运累计，允许修改，最终值正确分摊到工单。
- 工单关联炉次状态、操作人和时间随每次操作更新。
- 小程序计划时间显示 `plannedStartAt`，扫码匹配正确设备编码。
- 排产页在导航展开/收起及常用桌面宽度下无重叠，右侧两列表单和响应式降级正常。
