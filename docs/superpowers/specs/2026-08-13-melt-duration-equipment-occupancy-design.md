# 熔炼时长与设备占用排程设计

## 背景与目标

当前熔炼配方只维护材质、炉型、成分和配料信息，炉次只保存“计划出炉时间”。系统无法计算一炉生产对熔炼设备的完整占用区间，也无法在同一设备一天安排多次连续熔炼时识别时间冲突。

本次增加配方标准时长和炉次计划时间区间，用于：

- 根据配方自动计算预计完成时间；
- 形成可追溯的设备计划占用区间；
- 支持同一设备按时间连续安排多个炉次；
- 对重叠计划进行提示和二次确认，而不是强制禁止；
- 为后续设备日历、班次产能和实际执行偏差分析提供基础数据。
- 在合炉排产页面集中展示多台熔炼设备的当日占用情况。

本阶段不建设完整设备甘特图，不计算班次累计产能，也不引入设备停机、维护或换型日历。

本阶段会实现轻量级的 24 小时设备占用时间线，但不建设可拖动编辑、维修计划、自动找空档或阶段报工驱动的完整设备甘特排程系统。

## 方案选择

采用“配方标准时长 + 炉次时长快照 + 炉次占用区间”的方案。

不采用炉次实时读取配方时长。已下达炉次必须保存当时使用的时长快照，避免配方升级后历史计划时间发生变化。

不在本阶段建设独立设备排程日历。设备占用判断基于炉次自身的计划开始和预计完成时间完成，后续可平滑扩展。

## 配方模型

`MeltRecipe` 增加三个整数分钟字段：

- `meltingDurationMinutes`：熔炼时长；
- `transferDurationMinutes`：转运时长；
- `cleaningDurationMinutes`：清炉时长。

### 校验规则

1. 三个字段均必填，必须是大于等于 `0` 的整数。
2. 三项合计必须大于 `0`。
3. 新建、编辑、克隆和新版本必须完整保存或复制三个字段。
4. 已生效配方仍遵循现有状态机，不能直接编辑。需要先停用，再编辑形成下一版本草稿。
5. 历史配方迁移时三个字段默认 `0`，避免迁移失败。
6. 三项合计为 `0` 的历史配方不能用于新合炉排产，接口提示先维护配方时长。
7. 配方列表不强制增加三个独立列，避免主表过宽；查看和编辑页面展示完整时长，并可在列表按需要展示“总占用时长”。

### 管理端交互

配方基本信息区增加三个 `InputNumber`：

- 标签分别为“熔炼时长（分钟）”“转运时长（分钟）”“清炉时长（分钟）”；
- 同一行三列展示；
- 最小值为 `0`，只允许整数；
- 表单实时显示三项合计的“标准设备占用时长”。

## 炉次模型

`HeatOrder` 增加：

- `workshopCodeSnapshot`：熔炼车间编码快照；
- `workshopNameSnapshot`：熔炼车间名称快照；
- `plannedStartAt`：计划开始时间；
- `calculatedFinishAt`：根据配方时长自动计算的原始预计完成时间；
- `plannedFinishAt`：最终预计完成时间，允许人工调整；
- `meltingDurationMinutesSnapshot`：熔炼时长快照；
- `transferDurationMinutesSnapshot`：转运时长快照；
- `cleaningDurationMinutesSnapshot`：清炉时长快照；
- `occupancyDurationMinutesSnapshot`：三项标准时长合计快照；
- `finishTimeAdjusted`：预计完成时间是否被人工调整。

### 兼容字段

现有 `plannedOutputAt` 暂时保留，并在新炉次中同步保存为 `plannedFinishAt`，保证现有列表、详情和既有接口调用不立即失效。

新功能的业务判断统一使用 `plannedStartAt` 和 `plannedFinishAt`。后续完成兼容迁移后，可单独规划移除 `plannedOutputAt`。

炉次实际车间关系仍由目标熔炼设备的 `workshopCode` 决定。请求中的车间编码用于筛选和一致性校验，后端不能直接信任前端提交的车间名称或快照值。

### 时间计算

```text
occupancyDurationMinutesSnapshot
= meltingDurationMinutesSnapshot
+ transferDurationMinutesSnapshot
+ cleaningDurationMinutesSnapshot

calculatedFinishAt
= plannedStartAt + occupancyDurationMinutesSnapshot
```

默认：

```text
plannedFinishAt = calculatedFinishAt
finishTimeAdjusted = false
```

用户修改预计完成时间后：

```text
plannedFinishAt = 用户填写值
finishTimeAdjusted = plannedFinishAt != calculatedFinishAt
```

`plannedFinishAt` 必须晚于 `plannedStartAt`。修改配方或计划开始时间后，前端重新计算并覆盖预计完成时间，用户可以再次手动调整。

## 设备占用与冲突规则

### 占用区间

设备占用采用左闭右开区间：

```text
[plannedStartAt, plannedFinishAt)
```

因此上一炉预计完成时间等于下一炉计划开始时间时，不构成冲突。

### 参与冲突判断的炉次

- `WAITING`：参与；
- `IN_PROGRESS`：参与；
- `COMPLETED`：不参与新计划冲突；
- `CANCELED`：不参与。

本阶段冲突以计划占用区间为准。实际生产超时影响后续计划的能力，留待设备执行和动态调度阶段扩展。

### 冲突条件

同一设备下，已有炉次满足以下条件时发生冲突：

```text
existing.plannedStartAt < candidate.plannedFinishAt
AND existing.plannedFinishAt > candidate.plannedStartAt
```

### 软校验与二次确认

冲突不直接禁止下达，采用两阶段确认：

1. 前端选择设备、配方、计划开始和预计完成时间后，调用冲突检查接口。
2. 页面展示冲突炉次编号、状态、计划开始和预计完成时间。
3. 首次创建炉次时，后端在事务内再次查询冲突。
4. 若存在冲突且请求未携带确认标识，后端返回 `409` 和结构化冲突清单，不创建任何数据。
5. 前端弹出确认框，用户确认后携带 `confirmScheduleConflict: true` 重新提交。
6. 第二次提交时后端必须再次查询冲突，避免两次请求之间出现新计划。
7. 携带确认标识后允许创建，但仍保留容量、材质、配方、设备、班组和工单剩余数量等强校验。
8. 强制下达行为写入炉次 `CREATED` 过程记录，payload 保存冲突炉次编号、冲突区间和确认人。

## 后端 API

### 配方接口

现有配方列表、详情、新增、修改、克隆和新版本接口增加三个时长字段。所有写接口执行整数、非负和总时长校验。

### 排产选项

`GET /admin/production/melt-pool/options` 的配方选项增加：

```text
meltingDurationMinutes
transferDurationMinutes
cleaningDurationMinutes
occupancyDurationMinutes
durationConfigured
```

排产选项同时返回当前材质可用设备所归属的启用熔炼车间。车间选项按编码稳定排序并去重，只包含：

- 车间状态启用；
- 车间类型为熔炼；
- 车间下至少存在一台被当前材质已生效配方绑定、启用且容量有效的熔炼设备。

历史配方总时长为 `0` 时仍可在管理端识别，但在合炉排产中标记不可使用，并提示维护配方时长。

### 冲突检查

新增：

```text
POST /admin/production/heat-orders/check-conflicts
```

请求：

```json
{
  "furnaceCode": "EQ-MELT-IF-1T-01",
  "plannedStartAt": "2026-08-13T08:00:00+08:00",
  "plannedFinishAt": "2026-08-13T09:30:00+08:00"
}
```

响应返回冲突炉次数组，不产生副作用。接口用于提前提示，不能替代创建事务内的最终检查。

### 创建炉次

`POST /admin/production/heat-orders` 请求调整为：

```text
workshopCode
plannedStartAt
plannedFinishAt
confirmScheduleConflict
```

后端根据选择的已生效配方重新读取三个时长，生成时长快照和 `calculatedFinishAt`。前端不能提交或覆盖时长快照。

后端根据目标设备读取真实所属车间，并校验：

- 请求车间存在、启用且类型为熔炼；
- 目标设备属于请求车间；
- 执行班组属于请求车间；
- 配方绑定目标设备。

创建成功后保存真实车间编码和名称快照，不接受前端提交车间名称。

后端判断 `plannedFinishAt` 是否与自动计算值不同，并生成 `finishTimeAdjusted`。

创建事务继续使用 `Serializable`，并在同一事务内完成：

- 工单剩余数量复核；
- 单炉容量复核；
- 材质、配方、设备、班组关系复核；
- 配方时长复核；
- 设备时间冲突复核；
- 炉次、分配明细、数据归属和操作记录创建。

## 管理端合炉排产

将原“计划出炉时间”调整为：

- “计划开始时间”：必填；
- “预计完成时间”：必填，默认自动计算，允许修改。

交互顺序：

1. 选择熔炼车间；
2. 选择目标熔炼设备；
3. 选择已生效且已配置时长的配方；
4. 选择执行班组；
5. 输入计划开始时间；
6. 系统自动计算预计完成时间；
7. 用户可修改预计完成时间；
8. 页面异步显示设备时间冲突；
9. 提交时如有冲突弹出二次确认。

熔炼车间为必填字段，位于目标熔炼设备之前。选择车间后：

- 目标设备只显示该车间下当前材质可用的设备；
- 配方只显示与所选目标设备匹配的已生效配方；
- 班组只显示该车间下的启用班组；
- 切换车间时清空设备、配方和班组；
- 切换设备时清空配方和班组；
- 若刷新后原车间或设备已失效，相关表单字段立即清空，不能使用旧值提交。

页面同时展示：

- 熔炼时长；
- 转运时长；
- 清炉时长；
- 标准占用时长；
- 最终计划占用区间；
- 冲突炉次提示。

修改配方或计划开始时间时，重新计算预计完成时间并清除旧冲突检查结果。快速切换车间、配方、设备或时间时，旧请求不得覆盖新状态。

## 设备排程概览

合炉排产页面在现有待排工单和凑吨计算器下方增加“设备排程概览”，用于同时查看多台熔炼设备的当日状态与炉次占用区间。

### 筛选栏

筛选条件包含：

- 车间：只显示熔炼类型车间，默认当前首个可用熔炼车间；
- 日期：默认当前日期；
- 查询：按当前车间和日期手动刷新设备和炉次排程数据。

设备概览不进行定时自动刷新。用户点击“查询”时，只更新设备概览和时间线，不能重置上方正在编辑的合炉分配、表单字段或二次确认状态。

设备概览的车间筛选默认跟随上方排产表单当前选择的熔炼车间。用户可以在概览筛选中独立切换车间并点击查询；概览筛选变化不得反向修改上方正在编辑的排产车间、设备、配方或班组。

快速切换车间或日期并连续查询时，旧请求不得覆盖当前筛选条件。页面卸载后停止异步回写。

### 设备卡片

设备卡片数据来源为筛选车间下所有启用且配置有效单炉容量的熔炼设备，不要求设备当天存在炉次。

多设备采用响应式网格：

- 宽屏优先三列；
- 中等宽度两列；
- 窄屏单列；
- 卡片顺序按设备编码稳定排序；
- 卡片高度保持一致，文本超长时换行或省略，不互相挤压。

设备卡片展示：

- 设备名称；
- 单炉容量；
- 设备状态；
- 当前炉次或下一炉次编号；
- 材质牌号；
- 目标铁水重量；
- 包含工单摘要；
- 计划开始；
- 预计完成；
- 距离开始或预计完成的剩余时间。

本阶段设备状态只使用现有可靠数据：

- `生产中`：当前时间落在 `IN_PROGRESS` 炉次的占用区间；
- `待生产`：当前时间落在 `WAITING` 炉次的占用区间，或设备下一炉次尚未开始；
- `空闲`：当前没有生产中炉次，且当前时间不在任何待生产占用区间；
- `存在冲突`：当天存在两个或以上有效炉次占用区间重叠，可在基础状态旁增加警告标识。

设备卡片不展示“熔化中、浇注中、阶段进度、浇注倒计时”，因为现有执行模型没有阶段报工数据。也不提供“快速排产此设备”按钮。

查看历史或未来日期时：

- 不把查看时间误当作实时生产状态；
- 卡片展示该日期最早的有效炉次摘要，或显示“当天无排程”；
- 不显示基于当前时间的实时倒计时。

### 24 小时占用时间线

时间线固定展示所选日期的本地时间 `00:00–24:00`：

- 每台设备一行；
- 横轴按小时显示，宽度不足时允许横向滚动；
- 炉次块按计划开始和预计完成定位；
- 炉次块显示炉次编号、材质和状态；
- 待生产、生产中、已完成、时间冲突使用不同状态样式；
- 点击炉次块进入或打开炉次详情；
- 空闲区域只显示为空白或空闲背景，不提供快速排产操作；
- 时间线不支持拖动修改炉次。

设备占用块与所选日期窗口的交集为：

```text
visibleStart = max(plannedStartAt, selectedDate 00:00)
visibleFinish = min(plannedFinishAt, selectedDate next day 00:00)
```

跨日炉次只显示落在当前日期内的部分。例如炉次从前一天 `23:00` 到当天 `01:30`，当天时间线只显示 `00:00–01:30`。

结束时间等于当天 `00:00` 或开始时间等于次日 `00:00` 的炉次，与当前日期没有可见交集，不返回或不渲染。

### 排程概览接口

新增只读接口：

```text
GET /admin/production/equipment-schedule?workshopCode=...&date=YYYY-MM-DD
```

接口返回：

- 筛选车间信息；
- 当天时间窗口及服务端当前时间；
- 车间下全部有效熔炼设备；
- 每台设备当天相交的有效炉次；
- 已裁切的可见开始和结束时间；
- 当前/下一炉次摘要；
- 设备基础状态；
- 时间冲突标识和冲突炉次编号。

接口查询炉次范围采用区间相交条件，而不是仅按开始日期查询：

```text
plannedStartAt < nextDayStart
AND plannedFinishAt > selectedDayStart
```

已取消炉次不进入设备占用时间线。已完成炉次可以作为历史排程显示，但不参与新炉次冲突判断。

接口不得为每台设备逐一查询炉次，避免多设备时出现 N+1 查询。应一次读取车间设备、一次读取窗口内炉次，再按设备分组计算状态和冲突。

### 权限与数据范围

- 设备排程概览复用 `production.schedule.view`；
- 页面不提供新增、编辑、删除或快速排产动作；
- 设备卡片和时间线只返回排程展示所需的炉次、材质、重量和工单摘要；
- 设备占用是生产公共资源状态，具备排产查看权限的内部员工可查看所选车间完整设备占用，不能因炉次创建人数据范围而漏掉设备冲突；
- 供应商和客户用户不开放此管理端排程视图。

## 炉次列表与详情

炉次列表增加或替换为：

- 计划开始；
- 预计完成；
- 设备占用时长；
- 时间冲突标识。

炉次详情展示：

- 配方三个时长快照；
- 熔炼车间编码和名称快照；
- 自动预计完成时间；
- 最终预计完成时间；
- 是否人工调整；
- 下达时确认的冲突炉次信息。

历史炉次如果没有新时间字段，继续展示原“计划出炉时间”，不参与新的设备冲突判断。

## 权限与数据范围

- 冲突检查复用 `production.schedule.view` 或排产列表权限；
- 创建和冲突确认均要求 `production.schedule.create`；
- 冲突确认不是独立权限，属于下达炉次过程的一部分；
- 冲突清单只返回当前用户有权查看的必要炉次字段，不返回无关业务数据；
- 后端创建时仍检查目标设备上的全部有效占用，不能因数据行权限看不到冲突炉次而漏检。

## 并发与错误处理

1. 冲突检查接口只提供提示，不能保证提交时仍无冲突。
2. 创建炉次必须在事务内重新检查。
3. 两个用户同时安排同一设备重叠时间时：
   - 未确认冲突的请求返回 `409`；
   - 已明确确认的请求允许创建；
   - 所有强校验仍然生效。
4. 结构化冲突响应必须区分普通业务错误，前端只在明确的排程冲突时弹出二次确认。
5. 二次确认请求失败时不自动重试，不产生前端假成功。

## 数据迁移

1. 配方三个时长字段使用非空整数并默认 `0`。
2. 炉次新增时间和快照字段初期允许为空，以兼容历史数据。
3. 现有 `plannedOutputAt` 不删除。
4. 当前测试环境没有有效炉次时不需要回填；若正式部署前存在历史炉次，迁移脚本不得根据当前配方反向生成历史时长快照。
5. Prisma 迁移必须同时在本地临时测试 schema 和测试服务器执行验证。

## 测试计划

### 配方

- 三个时长均为非负整数时可保存；
- 负数、小数和三项合计为 `0` 时拒绝；
- 克隆和新版本完整复制时长；
- 历史零时长配方不能用于新排产；
- 配方升级不改变已下达炉次的时长快照。

### 时间计算

- 计划开始 `08:00`，时长 `60 + 15 + 15`，自动完成为 `09:30`；
- 人工改为 `09:45` 后设备占用结束为 `09:45`；
- 修改计划开始或配方后重新自动计算；
- 完成时间早于或等于开始时间时拒绝；
- 前后端跨时区计算结果一致。

### 冲突判断

- 区间部分重叠、完全包含和被包含均识别冲突；
- 新开始等于上一炉结束不冲突；
- 新结束等于下一炉开始不冲突；
- 不同设备不冲突；
- 已取消、已完成炉次不冲突；
- 待生产、生产中炉次参与冲突；
- 首次提交冲突返回 `409` 且不创建数据；
- 二次确认后允许创建并记录冲突信息；
- 二次提交时新增冲突能够被重新读取并记录。

### 既有排产规则

- 单炉容量、工单剩余数量和材质一致性继续生效；
- 配方必须已生效并绑定目标设备；
- 请求车间必须是启用的熔炼车间；
- 设备和班组必须同时属于请求车间；
- 并发分配同一工单不能超分；
- 测试继续使用临时 PostgreSQL schema，不影响业务数据。

### 管理端

- 自动完成时间、人工修改、时长摘要和冲突提示正确；
- 熔炼车间只显示当前材质存在可用设备的启用熔炼车间；
- 切换熔炼车间后设备、配方和班组联动清空并重新过滤；
- 伪造车间或提交其他车间的设备、班组时后端拒绝；
- 炉次详情使用车间快照，后续设备调整车间不改变历史炉次显示；
- 快速切换设备、配方和时间不会回写旧结果；
- 冲突二次确认只出现一次，取消后不创建炉次；
- 刷新失败和确认失败时不能重复或假成功；
- 列表和详情正确展示时间快照与人工调整标识。

### 设备排程概览

- 选择车间后返回该车间全部有效熔炼设备，包括没有炉次的空闲设备；
- 多设备按编码稳定排序，卡片和时间线设备顺序一致；
- 当天待生产、生产中、已完成炉次显示正确；
- 已取消炉次不显示；
- 没有炉次的设备显示空闲或当天无排程，不提供快速排产按钮；
- 跨日炉次分别在两天时间线中正确裁切；
- 相邻但不重叠的炉次不标冲突；
- 重叠炉次标识冲突并显示相关炉次编号；
- 查询实现无设备级 N+1；
- 手动点击查询只更新概览，不清空上方排产表单；
- 快速切换车间和日期不会回写旧请求；
- 历史和未来日期不显示错误的实时倒计时；
- 三列、两列和单列断点下设备卡片无重叠；
- 时间线在窄屏可横向滚动且炉次块仍可点击查看详情。

## 后续扩展

本设计提供设备计划占用区间。后续可增加：

- 工厂日历和班次内可用时间；
- 设备维护、停机和不可用时段；
- 实际开始、实际结束与计划偏差；
- 生产中超时对后续炉次的动态预警；
- 设备甘特图和拖动调整；
- 自动寻找下一可用开始时间。

这些能力应复用 `plannedStartAt`、`plannedFinishAt` 和时长快照，不改变本期已定义的占用区间语义。
