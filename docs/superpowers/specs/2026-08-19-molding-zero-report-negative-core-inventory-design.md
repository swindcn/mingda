# 造型零数量报工与砂芯负库存设计

## 目标

造型下芯支持多次报工。现场可能已经在前一次报工中录入全部实际产量，但误选“继续生产”，需要通过一条零数量报工关闭任务。同时，造型报工不得因账面砂芯库存不足而中断；允许把未登记的砂芯复用形成的差异记录为负库存，并保持工单、芯盒、批次和报工之间的完整追溯关系。

## 零数量报工

- `goodQty = 0` 且 `scrapQty = 0` 时允许提交。
- 零数量报工只允许 `finishTask = true`，不允许继续生产。
- 零数量报工必须填写 `earlyCompletionReason`，用于说明补充关闭原因。
- 零数量报工创建正常的 `MoldingReport`，记录报工单号、操作人、时间、结束原因和备注。
- 零数量报工不创建砂芯消费明细，不改变砂芯库存，也不修改或覆盖上一条报工。
- 任务按正常结束逻辑进入 `COMPLETED`；累计合格数低于计划量时，`completionType = SHORT`，保留原累计数量。

## 砂芯透支扣减

正常报工的砂芯需求继续按以下公式计算：

```text
本次砂芯需求 = (本次合格箱数 + 本次废品箱数) × 每箱砂芯需求
```

扣减规则：

1. 只查询当前生产工单、对应芯盒的来源批次，禁止跨工单借用。
2. 正库存按现有规则分配：`WARNING 优先 -> 最早过期 -> 最早生产`。
3. 正库存足够时，行为与现有实现一致。
4. 正库存不足时，先把所有可用正库存扣至 `0`，再将剩余差额透支到同工单、同芯盒的最后一个来源批次，使该批次 `currentQuantity` 变为负数。
5. 透支批次优先选择本次正常分配的最后一个批次；本次没有正库存时，选择该工单、芯盒最近产生的可追溯批次。
6. 如果该工单、芯盒从未产生来源批次，则禁止透支并返回“未找到可追溯的砂芯来源批次”。系统不得创建虚假生产批次。
7. 批次余额小于等于 `0` 时状态保持 `CONSUMED`。

每个受影响批次创建一条 `MoldingCoreConsumption`；同一批次同时承担正常扣减和透支时合并数量，满足数据库 `reportId + coreInventoryBatchId` 唯一约束。明细记录批次、芯盒、合计扣减数量、扣减前数量和扣减后数量；同时创建一条 `CoreInventoryLedger`，记录 `CONSUMED`、负数量变化、报工来源、操作人和报工单号。

## 齐套与净库存

- 造型任务齐套必须按当前工单、芯盒全部来源批次的正负余额净额计算。
- 计算公式为 `netAvailable = max(0, sum(currentQuantity))`，不能只汇总状态为 `AVAILABLE/WARNING` 且数量大于 `0` 的批次。
- 负余额参与抵扣后续新产生的正库存。例如历史余额为 `-6`，新批次增加 `10`，净可用量为 `4`。
- 具体领用仍优先扣减可用正批次；不足部分继续透支到可追溯批次。
- 负库存表示账实差异，不代表可领用实物，因此接口展示的可用数量最低为 `0`，但消费和流水保留真实负余额。

## 撤销报工

- 撤销继续按原 `MoldingCoreConsumption` 逐笔返还原批次。
- 透支造成的负数可以通过撤销恢复到 `0` 或正数。
- 批次返还后的状态通过统一批次状态计算函数重新确定；数量仍小于等于 `0` 时保持 `CONSUMED`。
- 零数量报工没有消费明细，撤销时只回滚任务累计和状态，不改库存。
- 已报废批次继续禁止直接撤销，避免绕过报废审计规则。

## 前端交互

- 小程序报工允许合格数、废品数同时为 `0`。
- 当两项都为 `0` 时，只允许选择“本任务已结束”，并显示必填的结束原因。
- 若用户选择“继续生产”后提交零数量，前端提示“零数量报工仅用于结束任务”。
- 非零报工沿用现有缺陷校验：废品数大于 `0` 时必须选择适用当前工序的缺陷代码，缺陷数量合计必须等于废品数。
- 前端不因页面缓存的砂芯库存阻止提交；后端在事务内锁定任务和批次并完成最终分配。

## 并发与错误处理

- 报工继续使用 `versionNo` 防止旧页面覆盖新状态，使用 `requestId` 防止重复报工。
- 在可串行化事务内锁定任务，并在修改每个批次前获取批次锁。
- 读取正库存、选择透支批次、写报工、写消费明细、修改批次、写流水和更新任务必须整体成功或整体回滚。
- 并发导致批次数量变化时重新执行事务；超过现有重试次数后返回冲突提示，由前端刷新。
- 无可追溯来源批次、任务状态不允许报工、零数量继续生产、零数量缺少结束原因等均返回明确业务错误。

## 测试范围

- 合格数和废品数均为 `0`，选择结束并填写原因：成功关闭任务，不产生库存消费。
- 零数量选择继续生产：拒绝。
- 零数量结束但未填写原因：拒绝。
- 正常库存充足：按 FIFO 扣减，余额不为负。
- 正常库存部分不足：先扣正库存，再透支来源批次，消费明细与流水数量合计等于需求。
- 所有来源批次余额为 `0`：从最近来源批次透支。
- 没有任何来源批次：拒绝并保持报工、库存和任务均不变。
- 负库存参与齐套净额，新批次入库后只显示抵扣后的净可用量。
- 撤销透支报工：原批次负余额和任务累计准确恢复。
- 重复 `requestId`：不重复透支和写流水。
- 两个并发报工：串行化后库存、消费明细和任务累计保持一致。

## 一期边界

- 本次不提供修改历史报工功能，纠错继续使用管理端撤销后重新报工。
- 本次不增加砂芯回收、复用或返库的独立业务单据；负库存作为账实差异保留。
- 后续若建设砂芯回收模块，应通过独立返库流水冲减负库存，不得直接改写历史消费记录。
