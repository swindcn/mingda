# 待生产炉次排程拖动调整设计

## 目标

允许管理端调整待生产熔炼任务的计划开工时间，并在设备排程甘特图中通过拖动同时调整时间和目标熔炉。时间轴继续按小时显示，拖动按 15 分钟吸附。所有修改走真实后端接口、事务、状态校验和版本号乐观锁。

## 范围

- 炉次详情页提供“调整排程”操作，可修改熔炼设备与计划开始时间。
- 合炉排产页设备排程甘特图支持待生产炉次跨设备拖动。
- 仅管理端提供调整入口，小程序只读取调整后的最新时间和设备。
- 仅 `WAITING` 炉次允许调整；生产中、转运中、已完成和已撤销炉次不可调整。
- 不改变配方、执行班组、分配工单、目标重量和标准时长。

## 权限

- 新增管理端按钮权限 `production.schedule.adjust`。
- 角色未配置该权限时，不显示详情页“调整排程”按钮，甘特图炉次不可拖动。
- 后端权限守卫必须校验该权限，前端隐藏仅用于交互体验。

## 后端接口

新增：

```text
PUT /api/admin/production/heat-orders/:id/schedule
```

请求：

```ts
{
  versionNo: number
  furnaceCode: string
  plannedStartAt: string
  confirmScheduleConflict?: boolean
}
```

响应继续使用统一结构 `{ code, message, data }`，其中 `data` 为更新后的炉次详情。

## 时间计算

- 新开始时间必须是有效时间，并由前端按 15 分钟吸附；后端不信任前端，必须再次校验分钟值为 `00/15/30/45` 且秒、毫秒为 0。
- 调整前的计划占用时长定义为 `plannedFinishAt - plannedStartAt`，调整后保持该时长不变。
- 新计划结束时间为 `newPlannedStartAt + originalPlannedDuration`。
- `calculatedFinishAt` 根据新开始时间加标准 `occupancyDurationMinutesSnapshot` 重新计算。
- `plannedOutputAt` 继续与新的最终计划结束时间同步，以兼容现有字段。
- `finishTimeAdjusted` 根据新的最终计划结束时间是否等于新的自动计算完成时间重新计算。

## 跨设备校验

甘特图只允许拖到当前车间查询结果中的设备行，因此一期不跨车间调整。后端仍需重新校验目标设备：

- 设备存在、启用且 `equipmentType = 熔炼炉`。
- 设备属于炉次当前熔炼车间。
- 设备容量能够承载炉次目标重量。
- 当前炉次绑定的配方适用于目标设备。
- 不自动更换配方、班组或其他业务字段。

目标设备不适用当前配方或其他条件不满足时，禁止保存并恢复原位置。

## 冲突与并发

- 冲突区间继续使用左闭右开规则 `[plannedStartAt, plannedFinishAt)`。
- 检查目标设备冲突时必须排除当前炉次自身。
- 首次发现冲突返回 HTTP `409`、`conflictCode = HEAT_SCHEDULE_CONFLICT` 和冲突炉次列表。
- 前端确认框同时展示设备、开始时间、结束时间变化和冲突明细；用户确认后携带 `confirmScheduleConflict = true` 再次提交。
- 保存条件同时包含 `id + WAITING + versionNo`。其他终端已经更新时返回 `409`，前端提示“数据已被其他终端更新，页面已刷新”，恢复拖动前位置并重新查询。
- 整个更新和过程记录写入同一数据库事务，失败不得产生部分数据。

## 过程记录

为 `HeatOrderAction` 增加 `SCHEDULE_ADJUSTED`，记录：

- 调整前后熔炉编码与名称。
- 调整前后计划开始和计划结束时间。
- 是否跨设备。
- 是否确认时间冲突及冲突清单。
- 操作人、操作时间和可选备注。

## 详情页交互

- 待生产且有 `production.schedule.adjust` 权限时显示“调整排程”。
- 弹窗包含目标熔炉和计划开始时间；预计结束时间只读自动计算。
- 设备下拉只返回当前车间、当前配方适用且容量足够的启用熔炼炉。
- 使用统一的操作前刷新、`versionNo` 乐观锁和 `409` 自动刷新机制。

## 甘特图拖动交互

- 基于 Pointer Events 和 `setPointerCapture` 实现，不新增拖拽依赖。
- 只有 `WAITING` 且当前用户有调整权限的炉次块可拖动。
- 指针移动超过约 5px 后进入拖动；未达到阈值仍按点击进入详情处理。
- 水平位置换算为选中日期的分钟数，并按 15 分钟四舍五入吸附；时间轴标签继续按小时显示。
- 垂直位置命中目标设备行，支持跨熔炉拖动。
- 拖动期间原位置显示虚线占位，目标位置显示炉次、目标设备、吸附后的开始与结束时间。
- 不兼容设备显示禁止落点；靠近时间轴左右边缘时自动横向滚动。
- 松手后先执行校验，再显示确认框。确认成功后重新查询设备排程；取消、接口失败或冲突未确认时恢复原位置。
- 允许开始时间吸附到当天 `00:00` 至 `23:45`，结束时间可以自然跨到次日。

## 前端组件边界

- `EquipmentScheduleOverview` 负责查询条件、设备行和刷新。
- 独立拖动工具负责坐标换算、15 分钟吸附、设备行命中和拖动状态，不复制后端业务校验。
- 独立排程调整操作负责预检、确认框、冲突二次确认、提交和 `409` 刷新，可由详情页和甘特图复用。
- API 类型和调用继续放在 `apps/admin/src/utils/production.ts`。

## 测试

### 后端接口

- 同设备调整时间成功，原计划时长保持不变。
- 跨设备调整成功并更新设备快照。
- 非 15 分钟时间、非待生产状态、配方不适用、容量不足、跨车间设备被拒绝。
- 冲突首次返回结构化 `409`，确认后保存。
- 冲突检测排除自身。
- 旧 `versionNo` 返回 `409`，不写过程记录。
- `SCHEDULE_ADJUSTED` 保存完整前后快照和操作人。

### 前端

- 分钟坐标按 15 分钟吸附，时间轴仍按小时显示。
- 跨设备行命中正确，非待生产炉次不可拖动。
- 点击与拖动阈值不会互相误触。
- 取消确认不调用修改接口，界面恢复原位置。
- 冲突确认、接口错误和并发 `409` 均刷新真实数据。
- 详情页与甘特图使用同一权限和调整操作。
