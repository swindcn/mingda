# 生产工单工艺路线执行设计

更新时间：2026-08-26

## 1. 背景与目标

生产工单已经锁定具体的工艺路线版本，但当前详情页中的“绑定工艺路线预览”只展示静态工序、默认设备和节拍。制芯任务和造型任务仍通过页面右上角生成，熔炼工单在创建后自动进入合炉排产池，工艺路线没有成为工单执行入口。

本次改造目标：

- 将工单锁定的工艺路线作为生产执行主视图。
- 在每个工序行展示任务是否已下达、实际执行进度、已排设备和班组。
- 在对应工序行完成任务下达或跳转至关联任务。
- 取消生产工单创建后自动进入熔炼排产池，改为在熔炼工序行手工下达。
- 保留制芯、熔炼、造型、浇注、落砂清理、成品终检各自已有的任务模型、状态机和报工逻辑，不新增重复的通用任务表。

## 2. 已确认业务规则

### 2.1 工序状态和进度

“工序状态”和“工序进度”是两个不同概念：

- 工序状态：表示当前工序对应的执行任务或待执行批次是否已经下达或生成。
- 工序进度：表示已下达任务的实际执行阶段及数量完成情况。

工序状态统一使用以下展示值：

- `待下达`：支持人工下达，但尚未生成任务或释放到排产池。
- `部分下达`：制芯等一个工序需要多张任务单，只有部分任务已生成。
- `已下达`：所需任务已经生成，或熔炼工单已经释放到合炉排产池。
- `等待上游`：浇注、落砂清理、成品终检由上游报工自动生成队列，当前尚未产生执行批次。
- `未接入`：路线节点暂未配置对应的生产执行模块。

工序进度由各业务模块的真实数据汇总，前端不根据标签或按钮自行推断。统一主状态包括：

- `-`：任务尚未下达。
- `待排产`、`待派工`、`待生产`。
- `生产中`、`转运中`、`部分完成`。
- `已完成`、`已取消`、`异常`。

数量进度保留各工序自身单位，例如：

- 制芯：`已完成砂芯数 / 计划砂芯数（件）`。
- 熔炼：`已完成分配件数 / 工单计划件数（件）`，同时可附带实际铁水重量。
- 造型下芯：`累计合格箱数 / 计划箱数（箱）`。
- 合型浇注：`累计浇注箱数 / 已生成待浇箱数（箱）`。
- 落砂清理：分别展示落砂和清理阶段，工艺路线仍只占一个节点。
- 成品终检：`已完成检验数 / 待检总数（件）`。

### 2.2 工序下达方式

人工下达：

- 制芯：继续调用现有制芯任务生成预览和生成接口；一个 BOM 含多个芯盒时允许生成多张任务单。
- 电炉熔炼：新增“下达熔炼”动作，将当前工单释放到合炉排产池，但不直接生成炉次。
- 造型下芯：继续调用现有造型任务生成预览和生成接口。

上游驱动：

- 合型浇注：由造型下芯报工生成待浇注批次。
- 落砂清理：由浇注报工生成待落砂批次，再在同一节点内流转到清理阶段。
- 成品终检：由清理报工生成待检批次。

上游驱动工序不提供“下达任务”按钮。队列未生成时显示“等待上游”；生成后显示“查看任务”。

### 2.3 熔炼手工下达

- 新建生产工单保存成功后不再自动出现在合炉排产池。
- 工单详情的熔炼节点显示“下达任务”。
- 点击下达时，后端返回并展示当前制芯任务及烘干进度。
- 制芯尚未全部完成只作为软提示，不阻止下达。现场可能在砂芯烘干阶段提前安排熔炼。
- 用户确认后，工单进入合炉排产池，由调度员继续进行凑吨、设备、配方、班组和时间排产。
- 重复下达必须幂等，已经释放的工单不能重复产生数据或重复记录。
- 本期不提供“撤回熔炼下达”。已有炉次仍使用原有撤销规则。

### 2.4 多任务跳转

同一工序可能关联多张任务单：

- 一个制芯节点可能按多个芯盒产生多张制芯任务。
- 一张生产工单可能拆分到多个炉次。
- 下游工序可能产生多个报工批次。

因此“查看任务”统一跳转到对应模块的数据列表，并自动携带 `workOrderId` 过滤当前工单。只有现有业务明确为单任务且列表不提供额外价值时，才允许直接进入详情。

## 3. 页面设计

### 3.1 工单详情页

保留现有“绑定工艺路线预览”卡片，改造为“工艺路线执行”表格。列定义如下：

| 列 | 内容 |
| --- | --- |
| 顺序 | 锁定路线节点的 `seqNo` |
| 工序编码 | 锁定路线节点的工序编码 |
| 工序名称 | 锁定路线节点的工序名称 |
| 工序状态 | 待下达、部分下达、已下达、等待上游或未接入 |
| 工序进度 | 实际执行状态标签和数量进度 |
| 设备 | 已排产或执行任务指定的设备；多个值去重展示 |
| 班组 | 已排产或执行任务指定的班组；多个值去重展示 |
| 操作 | 下达任务、查看任务或禁用态原因 |

设备和班组列规则：

- 只展示任务实际选择的数据，不再把工艺路线上的“适用设备”误认为已排设备。
- 多任务使用不同设备或班组时，表格显示前两项和“等 N 项”，悬浮展示完整清单。
- 尚未排产时显示 `-`。

操作列规则：

- 固定在表格右侧。
- 操作按钮遵循现有权限规则；无权限时不显示可执行动作。
- 制芯、电炉熔炼、造型下芯在待下达时显示“下达任务”。
- 已存在任务时显示“查看任务”。
- 上游驱动节点未产生数据时显示禁用文字“等待上游”，不显示伪操作按钮。
- 未接入执行模块的节点显示“暂未接入”。

页面右上角移除“生成制芯任务”“制芯任务”“生成造型下芯任务”“造型任务”等工序专属按钮。返回、编辑、关闭等工单级操作保持不变。

现有“关联熔炼任务”“制芯计划”和砂芯齐套明细本期保留，避免删除现有详情能力。工艺路线表格作为统一入口，后续确认信息完全重复后再单独精简。

### 3.2 对应模块筛选

各任务列表增加可选的 `workOrderId` 查询参数，并在页面查询条件中保留当前过滤状态：

- `/dashboard/production/core-tasks?workOrderId=...`
- `/dashboard/production/heat-orders?workOrderId=...`
- `/dashboard/production/molding-tasks?workOrderId=...`
- `/dashboard/production/pouring-tasks?workOrderId=...`
- `/dashboard/production/shake-clean-tasks?workOrderId=...`
- `/dashboard/production/inspection-tasks?workOrderId=...`

从任务详情返回列表时必须继续保留 `workOrderId`，符合项目统一的列表状态记忆规则。

## 4. 后端架构

### 4.1 工艺路线执行摘要服务

新增独立的 `WorkOrderRoutingExecutionService`，职责仅限：

- 读取生产工单锁定的工艺路线版本。
- 查询各节点对应的真实任务、队列和报工汇总。
- 将不同模块状态映射为统一的工序状态和工序进度 DTO。
- 根据当前用户权限返回可用动作，不执行具体工序业务。

该服务不复制制芯、造型、浇注等模块的写入逻辑。下达任务仍调用现有领域接口；熔炼释放使用新增的专用接口。

新增接口：

```text
GET /admin/production/work-orders/:id/routing-execution
POST /admin/production/work-orders/:id/melt-release
```

执行摘要响应结构：

```ts
type WorkOrderRoutingExecutionNode = {
  nodeId: string
  seqNo: number
  operationCode: string
  operationName: string
  module: 'CORE' | 'MELT' | 'MOLDING' | 'POURING' | 'SHAKE_CLEAN' | 'INSPECTION' | 'UNSUPPORTED'
  dispatchStatus: 'PENDING' | 'PARTIAL' | 'RELEASED' | 'WAITING_UPSTREAM' | 'UNSUPPORTED'
  progressStatus: string
  progressText: string
  progressCurrent: number | null
  progressTotal: number | null
  progressUnit: string
  equipmentNames: string[]
  teamNames: string[]
  taskCount: number
  action: 'CREATE' | 'RELEASE_MELT' | 'VIEW' | 'WAIT' | 'NONE'
  actionEnabled: boolean
  actionPermission: string
  actionHint: string
}
```

接口必须先执行生产工单的数据范围校验。工艺路线摘要的读取权限使用 `production.work_order.view`；节点动作还必须分别满足对应模块权限。

### 4.2 节点与执行模块映射

一期复用现有标准工序约定：

- `OP-CORE` 或工段为“制芯” -> `CORE`。
- `OP-MELT` 或工段为“熔炼” -> `MELT`。
- `OP-MOLD` 或工段为“造型” -> `MOLDING`。
- `OP-POUR` -> `POURING`。
- `OP-SHAKE` -> `SHAKE_CLEAN`。
- `OP-INSP` -> `INSPECTION`。
- 其他节点 -> `UNSUPPORTED`。

不根据中文工序名称做字符串包含判断。后续新增执行模块时再扩展明确映射，避免相似名称误判。

### 4.3 熔炼释放状态

`scheduleStatus` 继续表示工单已释放后的分配进度：`PENDING / PARTIAL / FULL`。不扩展该枚举承载“是否释放”语义。

`WorkOrder` 新增：

```text
meltReleasedAt        DateTime?
meltReleasedByUserId  String?
```

并建立操作人与 `User` 的可空关系。

规则：

- 新工单创建时 `meltReleasedAt = null`。
- 合炉排产池只返回 `meltReleasedAt IS NOT NULL`、未关闭且仍有剩余件数的工单。
- 手工下达在事务中锁定工单；若已释放则直接返回当前结果，保证幂等。
- 成功释放时写入时间和操作人，并为审计保留操作者快照或业务操作记录。
- 历史工单迁移时将 `meltReleasedAt` 回填为 `createdAt`，保持当前正在测试和执行的工单仍可见。

### 4.4 状态汇总来源

- 制芯：`CoreProductionTask`，忽略已取消任务后计算任务覆盖数、状态、设备和班组。
- 熔炼：`WorkOrder.meltReleasedAt`、`HeatOrderAllocation` 和未取消 `HeatOrder`。
- 造型：`MoldingTask` 及其累计报工。
- 浇注：`PouringMoldBatch` 和 `PouringReport`。
- 落砂清理：`ShakeBatch`、`ShakeReport`、`CleaningBatch` 和 `CleaningReport`，合并为同一节点的两阶段进度。
- 成品终检：`InspectionBatch` 和 `InspectionReport`，返修循环仍由终检模块状态机负责。

全部汇总以工单锁定的 `routingVersionId` 和具体 `routingNodeId` 为边界。历史工艺路线后续停用或升版不影响既有工单执行。

## 5. 权限设计

沿用现有细粒度权限：

- 制芯下达：`production.core_task.create`
- 造型下达：`production.molding.create`
- 查看对应任务：各模块的 `*.view`

新增权限：

```text
production.schedule.release
```

角色权限名称为“合炉排产-下达工单”，用于把工单释放到合炉排产池。它与 `production.schedule.create`（生成熔炼任务）分离，避免拥有工单下达权限的用户自动获得炉次创建权限。

后端权限守卫是最终安全边界。前端根据权限隐藏按钮，但不能替代后端校验。

## 6. 并发、错误和兼容处理

- 熔炼下达使用数据库事务和工单行锁，防止重复点击。
- 执行摘要只返回当前数据库状态，页面下达成功后必须重新获取工单和执行摘要。
- 下达接口若发现工单已关闭，返回明确错误。
- 制芯未完成时，执行摘要返回 `actionHint`，前端二次确认；后端不做硬拦截。
- 任务在其他终端发生变化时，生成、派工和报工接口继续使用各模块现有乐观锁或状态条件更新，不能依赖详情页旧状态。
- 已取消任务仍表示该工序曾经下达，工序状态保持“已下达”，工序进度显示“已取消”，操作只提供“查看任务”。是否允许重新生成由各业务模块现有规则决定，本次不绕过任务唯一约束。
- 历史任务缺少设备或班组快照时显示 `-`，不使用路线适用设备冒充已排设备。

## 7. 测试方案

### 7.1 接口测试

- 新建工单后不出现在合炉排产池，熔炼节点为待下达。
- 手工下达熔炼后进入排产池；重复下达不产生重复记录。
- 制芯未完成时返回软提示，但确认后仍可下达熔炼。
- 历史工单迁移后仍出现在原有排产池。
- 无 `production.schedule.release` 权限时接口返回 403。
- 无生产工单数据权限时不能读取执行摘要或下达熔炼。
- 路线版本停用后，锁定该版本的历史工单仍能正确汇总和下达。

### 7.2 状态映射测试

- 多芯盒制芯任务分别覆盖待下达、部分下达、已下达和已完成。
- 一个工单分配到多个炉次时，汇总设备、班组和件数正确。
- 造型任务从待派工、待生产、生产中到已完成的映射正确。
- 浇注、落砂清理和终检在上游队列未生成时显示等待上游，生成后显示查看任务。
- 落砂与清理两阶段不拆成两个路线节点。
- 未接入模块的自定义工序不显示可执行按钮。

### 7.3 管理端测试

- 工单详情右上角不再出现工序专属生成按钮。
- 工艺路线表格操作列固定右侧，按钮受实际角色权限控制。
- 点击下达制芯、熔炼和造型后，当前行状态立即刷新。
- 点击查看任务进入对应列表并自动按工单过滤；返回后过滤条件仍保留。
- 多设备和多班组展示不撑宽表格，完整内容可查看。

### 7.4 回归测试

- 原有制芯、熔炼、造型、浇注、落砂清理和终检的生成、派工、报工、撤销流程保持通过。
- 合炉凑吨仍允许同材质多个已释放工单合并。
- 工单数据范围、菜单权限和按钮权限不被绕过。
- API、管理端和小程序构建通过；本次不改变小程序生产任务执行入口。

## 8. 本期不做

- 不建立统一通用工序任务表。
- 不把所有路线节点改为手工下达。
- 不对“制芯未完成时下达熔炼”做硬拦截。
- 不提供熔炼下达撤回。
- 不改造小程序端的任务生成入口；小程序继续执行已生成任务。
- 不为尚未接入生产执行模块的自定义工序制造本地状态或假成功。
