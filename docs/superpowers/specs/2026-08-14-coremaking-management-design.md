# 制芯工序与砂芯库存管理设计

## 1. 目标与范围

本期新增独立的制芯任务、现场报工、砂芯批次库存和保质期管理能力。功能复用生产工单锁定的 BOM 版本与工艺路线版本，并使用 BOM 芯件比、BOM 芯盒保质期和芯盒档案穴数完成任务拆分与数量计算。

本期包含：

- 生产工单详情手动生成制芯任务。
- 制芯任务派工、调整、开始、分批报工和取消。
- 每次报工生成砂芯批次与可打印二维码标签。
- 砂芯批次烘干确认、可用库存、临期、超期、冻结和报废管理。
- 生产工单详情中的砂芯任务汇总与齐套看板。
- 管理端和微信小程序制芯执行入口。
- 为后续造型下芯预留批次校验和库存扣减领域接口。

本期不包含：

- 生产工单提交时自动生成制芯任务。
- 造型任务、造型排产、下芯领用页面。
- 工程变更审批。
- 指定型号蓝牙或网络标签打印机协议集成。

## 2. 关键业务规则

### 2.1 任务生成入口

- 生产工单创建时已经锁定 `routingVersionId` 和 `bomVersionId`。
- 生产工单详情根据锁定的工艺路线版本判断是否包含所属工段为“制芯”的工序节点。
- 不含制芯节点时不显示“生成制芯任务”按钮，页面显示“该工单无需制芯”。
- 包含制芯节点时显示“生成制芯任务”。所有 BOM 芯盒均生成任务后，入口替换为“查看制芯任务”。
- 包含制芯节点但锁定 BOM 未配置芯盒时，点击生成入口返回明确配置错误。
- 制芯任务只允许人工触发生成，不随生产工单创建自动产生。

### 2.2 拆单粒度与计算

制芯任务最小粒度为 `生产工单 + 芯盒编码`，同一工单的不同芯盒必须生成不同任务。同一组合建立唯一约束，禁止重复生成。

生成工作台按 BOM 中尚未生成任务的每套芯盒展示一行，预计废品率默认 `0%`，允许逐行修改：

```text
计划需求量 = 向上取整（生产工单计划数量 × BOM 芯件比 ×（1 + 预计废品率））
计划压盒次数 = 向上取整（计划需求量 ÷ 芯盒穴数）
```

任务生成时保存以下快照，后续 BOM、芯盒或工艺路线调整不得改变已下达任务：

- 产品、生产工单、BOM 编码和版本。
- 工艺路线、制芯工序节点。
- 芯盒编码、名称、所属模具、穴数。
- 芯件比、保质期小时数、预计废品率。
- 计划需求量和计划压盒次数。

若 BOM 保质期为空，表示该砂芯不设置自动失效时间；仍可报工、烘干和领用，但不进入临期与超期计算。

### 2.3 派工约束

- 生成任务时逐行选择制芯工序节点、设备、班组和计划时间。
- 若路线有多个制芯节点，必须明确选择任务所执行的节点。
- 设备优先限定为该制芯节点配置的启用设备。
- 班组限定为设备所属车间的启用班组。
- 待派工任务补齐设备、班组和计划时间后进入待生产。
- 尚未报工的待生产任务允许调整派工；已有报工后不允许替换设备或班组。

### 2.4 多次报工

- 一张制芯任务允许多次报工，每次报工生成一条报工记录和一个独立砂芯库存批次。
- 报工保存实际设备、班组、操作人、混砂批次、合格数、报废数、废品原因、烘干要求和操作时间。
- 累计合格数量达到计划需求量时，任务自动完成。
- 允许超产，但需保留计划量、累计合格量和超产量，不做强拦截。
- 任务状态：`PENDING_DISPATCH` 待派工、`WAITING` 待生产、`IN_PROGRESS` 生产中、`COMPLETED` 已完成、`CANCELED` 已取消。
- 使用 `versionNo` 乐观锁，防止管理端和小程序对旧页面重复操作。

## 3. 数据模型

### 3.1 CoreProductionTask

制芯任务主表，与 `WorkOrder`、`CastingBomVersion`、`ProcessRoutingNode`、`CoreBoxMaster`、设备、班组建立真实 Prisma relation。

主要字段：

- `code`：任务编码，全局唯一。
- `workOrderId`、`bomVersionId`、`routingNodeId`、`coreBoxCode`。
- 产品、BOM、路线、工序、芯盒、模具名称快照。
- `quantityPerProductSnapshot`、`cavityCountSnapshot`、`shelfLifeHoursSnapshot`。
- `expectedScrapRate`、`plannedQuantity`、`plannedPressCount`。
- `equipmentCode`、`teamCode`、`plannedStartAt`。
- `qualifiedQuantity`、`scrapQuantity`、`status`、`versionNo`。
- 创建人、开始人、完成人、取消人及对应时间。

唯一约束：`@@unique([workOrderId, coreBoxCode])`。

### 3.2 CoreProductionReport

保存每次报工事实，与任务和生成的砂芯批次关联。

主要字段：实际设备、班组、操作人、混砂批次、班次、合格数、报废数、废品原因、是否需要烘干、备注和报工时间。

### 3.3 CoreInventoryBatch

保存砂芯实物批次和当前库存。

主要字段：

- 批次编码、二维码内容。
- 任务、报工、产品、芯盒及快照关系。
- 入库数量、当前数量。
- 烘干要求、烘干状态、烘干设备、确认人和确认时间。
- 保质期小时快照、保质期起算时间、失效时间。
- 库存状态、冻结/报废原因、`versionNo`。

批次编码格式：`CORE-[芯盒编码]-[YYYYMMDD]-[班次]-[3位流水]`。流水号通过数据库事务锁或唯一冲突重试生成。

### 3.4 CoreInventoryLedger

保存不可变库存流水，动作至少包括：`PRODUCED` 入库、`CONSUMED` 领用、`LOCKED` 冻结、`UNLOCKED` 解冻、`SCRAPPED` 报废、`ADJUSTED` 调整。

流水保存批次、数量变化、变化后数量、业务来源类型和来源 ID、操作人、原因和时间。后续造型下芯通过该表形成工单与砂芯批次追溯关系。

## 4. 烘干与保质期状态机

- 报工选择“无需烘干”：批次直接进入 `AVAILABLE`，保质期从报工时间开始计算。
- 报工选择“需要烘干”：批次进入 `UNDRIED`，库存不可领用。
- 烘干确认记录确认人、确认时间和烘干设备，随后进入 `AVAILABLE`；保质期从烘干确认时间开始计算。
- 有保质期且剩余时间小于 24 小时时，状态转为 `WARNING`。
- 有保质期且剩余时间小于等于 0 时，状态转为 `EXPIRED`，库存自动冻结，禁止领用。
- 批次支持人工 `LOCKED` 和 `SCRAPPED`。报废后库存数量归零并写流水。
- 定时任务周期更新临期和超期状态；所有读取、报工、烘干及未来领用操作仍必须实时重新计算，不能只依赖定时任务。

## 5. 齐套计算与未来造型接口

生产工单齐套看板按工单锁定 BOM 中的芯盒逐行展示：芯件比、需求总量、累计报工、当前可用库存、待烘干数量、最短剩余保质期、缺口和齐套状态。

可用库存按芯盒编码汇总，不强制限定为当前生产工单产生的批次；同一产品 BOM 所需的相同砂芯允许跨生产批次使用。只统计已烘干或免烘干、未过期、未冻结且未报废的库存。

为后续造型模块提供领域服务：

```ts
validateCoreConsumption(workOrderId, batchCode, quantity)
consumeCoreBatch(workOrderId, batchCode, quantity, operatorContext)
```

校验顺序：批次存在、当前产品 BOM 包含该芯盒、批次已烘干或免烘干、未超期或冻结、库存充足。`WARNING` 临期批次仍允许使用并优先领用。扣减操作使用事务与乐观锁，写入库存流水，禁止负库存。未来造型模块优先按最早失效批次领用。

本期实现并测试服务接口，但不提供造型任务、扫码领用页面或实际领用入口。

## 7. 页面与交互

### 7.1 管理端

“生产管理”新增“制芯任务”和“砂芯库存”。页面遵守现有标准：查询和新增/业务按钮位于标题右侧；数据列可横向滚动并拖动宽度；操作列固定右侧；实际授权操作超过三个时进入“更多”。

制芯任务列表提供状态标签、任务详情和派工操作。生成工作台从生产工单详情进入，以芯盒为行展示计算参数和派工字段。

砂芯库存列表按待烘干、可用、临期、超期、冻结、报废筛选，展示批次、芯盒、数量、烘干状态、失效时间和剩余时长。

标签提供管理端打印视图，包括二维码、砂芯名称、批次号、数量、生产时间、失效时间和烘干状态。使用浏览器打印，不绑定具体打印机协议。

### 7.2 小程序

首页新增“制芯任务”入口。普通员工只查看其所属执行班组任务，超管可查看全部。

列表支持下拉刷新和待生产/生产中/已完成页签。详情支持开始、多次报工、扫码录入混砂批次、批次标签预览和烘干确认。派工、取消、冻结和报废仅由管理端执行。

## 8. 权限与数据范围

管理端权限：

- `production.core_task.view/create/dispatch/edit/cancel/report/dry`
- `production.core_inventory.view/dry/lock/scrap`

小程序权限：

- `mini.production.core.view/start/report/dry`

菜单、页头按钮、行操作和后端接口使用相同权限键。管理端列表继续使用现有数据范围规则；小程序任务额外限制为当前用户所属执行班组，超管例外。后端是最终权限边界。

## 9. 并发与错误处理

- 批量生成任务、任务累计数量、批次创建和入库流水必须在同一事务中完成。
- 重复任务由数据库唯一约束和业务错误共同阻止。
- 报工、烘干、冻结、报废和未来库存扣减使用 `versionNo` 防止旧页面覆盖新状态。
- 并发批次编码冲突时自动重试，不向用户暴露数据库错误。
- 所有接口保持统一 `{ code, message, data }` 返回格式。
- 关联资料失效、设备与班组车间不一致、非法状态流转和数量非法时返回明确中文错误。

## 10. 测试范围

- 无制芯路线不返回任务生成能力；有制芯路线且 BOM 无芯盒时明确报错。
- 一工单多芯盒拆为多任务，芯件比、废品率、穴数和向上取整计算正确。
- 重复生成、非法设备/班组、越权操作被拒绝。
- 多次报工生成多个唯一批次，累计合格量达到计划后任务完成，超产保留。
- 待烘干批次不计可用库存；烘干后按确认时间计算失效时间。
- 无保质期批次不进入临期和超期；有保质期批次按 24 小时阈值进入临期并在到期后冻结。
- 冻结、报废、齐套统计和未来领用校验只使用有效库存。
- 并发报工、烘干和库存扣减不产生重复批次、重复流水或负库存。
- 管理端、小程序菜单及按钮权限与 API 权限一致。
- 管理端构建、小程序构建、Prisma 同步和 Docker 环境回归均通过。
