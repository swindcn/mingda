# 模具多芯盒与 BOM 芯件比设计

## 1. 目标

修正现有模具建档只处理一套芯盒的限制，使一套模具可以关联水道芯、曲轴箱芯、油道芯等多种芯盒，并由铸造 BOM 配置每种芯盒对应单件产品所需的砂芯数量，为后续制芯任务计算提供稳定数据源。

本次同时压缩模具档案、芯盒档案和 BOM 工装区的界面密度，但不改变现有菜单、权限键和档案独立维护入口。

## 2. 业务边界

- 模具档案定义工装主数据及其可使用的芯盒集合。
- 芯盒档案定义芯盒编码、名称、所属模具、寿命、状态、图片和备注。
- BOM 版本定义某产品使用哪些模具、哪些芯盒，以及每件产品需要多少个对应砂芯。
- 芯件比不属于芯盒档案，因为同一芯盒用于不同产品时可能有不同数量。
- 后续制芯任务按已生效 BOM 中的 `生产数量 × 芯件比` 计算理论需求。
- 芯盒工装不重复进入物理用料领料计算；砂芯物料损耗仍由 BOM 物理用料明细维护。

## 3. 数据关系

```text
Product
  -> CastingBom
    -> CastingBomVersion
      -> CastingBomVersionMold -> MoldMaster
      -> CastingBomVersionCoreBox(quantityPerProduct) -> CoreBoxMaster

MoldMaster
  -> CoreBoxMaster[]
```

### 3.1 模具与芯盒

继续使用现有真实 Prisma 一对多关系：

- `MoldMaster.coreBoxes: CoreBoxMaster[]`
- `CoreBoxMaster.moldCode -> MoldMaster.code`

不增加 JSON 字段或额外中间表。`MoldMaster.hasCoreBox` 不再由用户手工维护，接口根据关联芯盒自动返回；数据库字段暂时保留用于兼容旧数据和现有列表。

### 3.2 BOM 芯件比

`CastingBomVersionCoreBox` 新增：

- `quantityPerProduct Decimal @default(1) @db.Decimal(12, 4)`

该字段是 BOM 版本快照的一部分，必须大于 `0`。历史记录通过数据库默认值补为 `1`。

## 4. 模具建档规则

模具新增和编辑接口统一接收：

```ts
interface MoldCoreBoxInput {
  code: string
  name: string
  maxLife?: number
  usedLife?: number
  images: string[]
  status: '启用' | '停用'
  remark?: string
}

interface MoldInput {
  // 现有模具字段保持不变
  coreBoxes: MoldCoreBoxInput[]
}
```

保存规则：

1. 模具及芯盒在同一个 Prisma 事务中保存。
2. 芯盒编码全局唯一，同一请求内不允许重复。
3. 已属于其他模具的芯盒编码不能被当前模具接管。
4. 请求中新增的芯盒创建档案；已有且属于当前模具的芯盒更新档案。
5. 数据库已有但本次请求中被移除的芯盒改为“停用”，不删除。
6. 未保存的新芯盒行在前端移除时不产生数据库数据。
7. 被 BOM 历史版本引用的芯盒可修改名称、寿命、图片和状态，但不能改到其他模具。
8. 独立芯盒档案页只有在没有 BOM 引用时才允许真正删除。
9. 从模具开发单建档时，收货图片继续默认带入模具；新增芯盒时可复用这些图片，用户可删除或补充。

## 5. BOM 规则

BOM 请求中的芯盒结构由 `coreBoxCodes: string[]` 升级为：

```ts
interface BomCoreBoxInput {
  coreBoxCode: string
  quantityPerProduct: number
}

interface BomPayload {
  // 其他字段保持不变
  moldCodes: string[]
  coreBoxes: BomCoreBoxInput[]
}
```

交互与校验：

1. 选择模具后，自动追加该模具下全部启用芯盒，芯件比默认为 `1`。
2. 用户可以移除不适用于当前产品的芯盒，也可以从已选模具的启用芯盒中重新添加。
3. 取消模具时同步移除该模具对应的芯盒配置。
4. 芯件比支持小数，必须大于 `0`。
5. 同一 BOM 版本不能重复配置同一芯盒。
6. 新保存的芯盒必须启用且属于已选模具。
7. 已停用的历史芯盒仍可在查看态显示，但不能新增到草稿。
8. 新版本完整复制模具、芯盒和芯件比。
9. 同产品版本复制与跨产品克隆继续遵循现有工装过滤规则，并在保留芯盒时同时保留芯件比。
10. API 暂时兼容旧 `coreBoxCodes[]` 请求，并按芯件比 `1` 归一化；响应继续保留 `coreBoxCodes` 作为兼容字段，同时以 `coreBoxes[]` 为新界面的正式数据源。

## 6. 界面设计

### 6.1 模具档案弹窗

新增、查看、编辑使用同一个约 `1080px` 的紧凑分区弹窗：

- 基础信息采用三列栅格。
- 型腔数、使用寿命、已用次数同一行显示。
- 模具图片独占一行，继续使用现有方形多图组件。
- 取消“是否有芯盒”人工开关，改为“芯盒明细（N）”区块。
- 芯盒明细字段：编码、名称、使用寿命、已用次数、状态、图片、备注、操作。
- 图片列显示缩略图数量和编辑入口，避免多图直接撑高表格。
- 查看态只读；编辑态支持新增、修改和停用。
- 已停用芯盒默认显示灰色状态，保证历史关系可见。

### 6.2 芯盒档案弹窗

- 保留独立新增、查看、编辑入口。
- 使用紧凑两列或三列布局。
- 关联模具、编码和名称优先显示；寿命与次数同一行；图片和备注各占一行。
- 手机号、芯件比等与档案无关的字段不进入本页面。

### 6.3 BOM 工装区

- 第一行保留生产模具多选。
- 芯盒由多选框改为配置表。
- 表格列为：所属模具、芯盒编码、芯盒名称、芯件比、状态、操作。
- 查看态不显示操作列；编辑态提供移除和重新添加。
- 整体沿用 BOM 页面现有标题、按钮、输入高度和表格样式。

## 7. 接口与错误处理

- 模具新增、编辑必须使用事务，任一芯盒校验失败时模具和所有芯盒均不保存。
- 错误消息必须包含冲突芯盒编码，例如“芯盒编码 CORE-WATER-01 已属于模具 MOLD-002”。
- BOM 保存必须在后端重新校验芯盒状态、所属模具、唯一性和芯件比，不能依赖前端联动。
- 删除约束继续使用真实外键与引用计数；不做前端假删除。
- DTO 对历史空值统一返回 `quantityPerProduct: 1`。

## 8. 测试标准

1. 一个模具一次创建水道芯、曲轴箱芯、油道芯三套芯盒，刷新后完整存在。
2. 编辑模具新增第四套、修改已有芯盒、移除一套；被移除芯盒变为停用。
3. 模具查看和编辑完整回填全部芯盒，不再只显示第一条。
4. 重复芯盒编码、跨模具接管编码时事务整体回滚。
5. BOM 选择模具自动带出全部启用芯盒，默认芯件比均为 `1`。
6. BOM 保存芯件比 `1/2/4` 后刷新、查看、新版本复制均保持一致。
7. 芯件比为 `0`、负数、重复芯盒或芯盒不属于已选模具时接口拒绝。
8. 历史 `coreBoxCodes[]` 请求和历史数据库记录按芯件比 `1` 正常读取。
9. 模具档案、芯盒档案和 BOM 的查看/编辑弹窗在常见桌面宽度下无字段重叠，并显著减少纵向高度。
10. 管理端构建、API 构建、Prisma 校验、接口脚本和浏览器回归全部通过。

## 9. 非本期范围

- 不在本次创建制芯任务菜单和执行流程。
- 不增加砂芯损耗、批次、重量、合格率字段。
- 不改变工艺路线中的砂芯批次校验规则。
- 不删除 `MoldMaster.hasCoreBox` 数据库字段；待所有调用方迁移后再单独清理。
