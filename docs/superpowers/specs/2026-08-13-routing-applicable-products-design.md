# 工艺路线适用产品独立维护设计

日期：2026-08-13

## 目标

将工艺路线的工序编排与适用产品维护拆分为两个标签页。新产品或半成品出现后，可以直接加入已生效路线，不需要停用路线或创建新版本；工序节点、前后关系、设备和工艺参数的变化仍按原版本规则处理。

## 页面设计

工艺路线新增、编辑和查看页面统一提供两个标签页：

1. `工艺线路`：显示路线基本信息、标准工序库、路线画布和节点配置。
2. `适用产品`：显示当前路线版本关联的产品和半成品数据列表。

适用产品列表字段：产品编码、产品名称、物料类型、材质牌号、是否默认路线、操作。列表右上角提供查询和添加按钮；添加通过弹窗多选物料管理中的成品、半成品，已关联产品不再出现在候选项中。删除使用简短图标操作并二次确认。

新建路线尚未保存时，适用产品标签页允许先选择产品，数据随路线草稿首次保存一并提交。路线已经保存后，适用产品增减走独立接口，不要求重新保存工艺线路。

## 状态与权限

- 草稿：可以维护工艺线路和适用产品。
- 已生效：工艺线路只读，但拥有 `model.routing.edit` 权限的用户可以增减适用产品。
- 已停用：工艺线路和适用产品均只读。
- `model.routing.view` 控制两个标签页的查看。
- `model.routing.edit` 控制已保存路线的适用产品增减，不新增权限节点。
- 新建页面由 `model.routing.create` 控制首次选择与保存。

## 后端接口

保留创建和草稿编辑接口中的 `productCodes`，用于首次保存和草稿整体保存。新增独立接口：

`PUT /admin/modeling/routings/:id/applicable-products`

请求体：

```json
{
  "productCodes": ["ITEM-A", "ITEM-B"]
}
```

接口以请求中的完整集合覆盖当前路线版本的适用产品关系，并执行以下校验：

- 路线版本存在且当前用户可见。
- 路线状态不是 `DISABLED`。
- 调用者拥有 `model.routing.edit`。
- 所有编码都来自物料管理，且类型为成品或半成品。
- 删除产品关系时，如果该产品的默认路线指向当前版本，同一事务内删除默认路线关系。
- 新增、删除和默认关系清理必须在同一数据库事务中完成。

接口返回更新后的完整路线详情。已生效路线不会因为适用产品调整而改变版本号或状态。

## 数据关系与历史

继续使用现有 `RoutingApplicableProduct`，关系仍挂在 `ProcessRoutingVersion`。本次不迁移到路线主表，避免扩大数据模型改动。

生产工单创建时已经锁定 `routingVersionId` 和路线快照。后续从适用产品中移除某产品，不影响已创建生产工单；只影响该产品之后新建工单时能否选择该路线。

创建新路线版本时，继续复制来源版本的适用产品集合。发布新版本时，默认路线只迁移仍在新版本适用集合内的产品。

## 错误处理

- 已停用路线修改：`已停用路线不能维护适用产品`。
- 物料不存在：`关联产品或半成品不存在`。
- 包含原材料、辅材或工装：`工艺路线只能关联成品或半成品`。
- 权限不足：统一返回 `无权执行当前操作`。

前端接口失败后保留当前列表，不做本地假成功，并重新读取详情确认服务端状态。

## 测试范围

1. 草稿路线可以通过独立接口增减适用产品。
2. 已生效路线可以直接增减适用产品，状态和版本不变。
3. 已停用路线禁止修改。
4. 原材料和不存在的物料禁止关联。
5. 移除默认产品时同步删除 `ProductDefaultRouting`。
6. 没有编辑权限时按钮隐藏，直接请求接口也被拒绝。
7. 新建页面选中的产品随首次保存落库。
8. 产品调整后刷新页面仍以数据库结果为准。
9. 已锁定该路线的历史生产工单不受关系调整影响。
