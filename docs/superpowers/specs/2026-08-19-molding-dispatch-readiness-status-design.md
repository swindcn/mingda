# 造型任务派工与齐套状态分离设计

## 目标

造型下芯任务的派工进度与砂芯齐套结果必须分开表达。砂芯未齐套不得覆盖任务已经完成派工的事实。

## 状态模型

任务主状态为：

```text
PENDING（待派工）
  -> DISPATCHED（已派工）
  -> IN_PROGRESS（生产中）
  -> COMPLETED（已完工）

PENDING / DISPATCHED -> CANCELED（已取消）
```

砂芯齐套保持为独立的实时计算结果：

- `READY`：已齐套。
- `WAITING_CORE_TASK`：同工单制芯任务尚未完成。
- `INSUFFICIENT_CORE`：制芯已完成，但当前可用砂芯数量不足。

齐套结果不再生成 `WAITING_CORE` 任务显示状态。

## 业务规则

- 新建造型任务的现有表单必须选择生产线和执行班组，保存后视为已完成派工，持久化状态为 `DISPATCHED`。
- 对待派工或已派工任务执行“派工/调整派工”，保存后状态为 `DISPATCHED`。
- `DISPATCHED` 状态仍允许调整生产线、班组和计划开始时间，前提是任务未开工且无有效报工。
- 只有 `DISPATCHED` 且实时砂芯齐套结果为 `READY` 时，才允许开始生产。后端继续在开工事务内重新计算齐套，不依赖前端页面旧数据。
- 未齐套时不显示“开始生产”按钮，但不展示顶部警告。砂芯需求、可用数量和缺口继续在齐套明细中展示。
- 待派工和已派工任务可取消；生产中任务不通过本次调整改变取消规则。

## 前端交互

- 管理端和小程序状态标签增加“已派工”，列表页签改为：全部、待派工、已派工、生产中、已完工、已取消。
- 任务列表增加紧凑的“砂芯齐套”列，显示已齐套或未齐套，不作为主状态筛选。
- 详情页移除“砂芯尚未齐套，当前任务不能开工”顶部警告。

## 数据与兼容

- Prisma `MoldingTaskStatus` 增加 `DISPATCHED`。
- 新建和派工接口写入 `DISPATCHED`。
- 已有 `PENDING` 数据不做自动批量转换，以避免无法区分“只有预填分配”与“已正式派工”的历史语义。对历史任务重新执行派工后进入 `DISPATCHED`。

## 验证

- 砂芯未齐套时派工成功，任务状态为 `DISPATCHED`，齐套状态仍为未齐套。
- 未齐套的已派工任务不允许开工。
- 补齐同工单砂芯后，已派工任务允许开工并进入 `IN_PROGRESS`。
- 管理端与小程序不再把未齐套显示为任务主状态，也不显示顶部警告。
