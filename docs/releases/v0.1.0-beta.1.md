# v0.1.0-beta.1 外测发布说明

发布日期：2026-08-27

## 发布定位

本版本为闽大铸件 MES 的第一版外部测试基线，覆盖管理端、API 和微信小程序三端。线上环境用于业务流程验证，不作为最终生产验收版本。

## 主要功能

- 基础资料：部门、用户、角色权限、客户、供应商、物料和字典管理。
- 模具业务：模具开发、收发货、试产/量产/评判、模具及多芯盒建档。
- 生产建模：车间产线、班组、设备、材质牌号、熔炼配方、铸造 BOM、工序和工艺路线。
- 生产执行：生产工单、节点化任务下达、制芯、熔炼与转运、造型下芯、合型浇注、落砂清理、成品终检。
- 移动执行：小程序端模具跟单及制芯、熔炼、造型、浇注、落砂清理、终检报工。
- 权限体系：菜单、数据列表、按钮、数据范围和小程序菜单权限。

## 关键业务约束

- 生产工单锁定创建时的 BOM 与工艺路线版本，后续主数据停用不影响历史工单执行。
- 熔炼任务由工单工艺路线节点手工释放，制芯未完成只提示，不做硬拦截。
- 同一工单的多个熔炼节点独立释放，炉次分配绑定具体工艺路线节点。
- 下游任务由上游报工数据驱动，前端不制造本地任务或假成功状态。
- 所有写操作以后端权限、数据范围、状态和版本校验为最终边界。

## 数据升级

发布前必须备份 PostgreSQL。当前外测服务器仍使用旧版线性工艺路线结构，代码同步后按以下顺序执行：

1. `npm --prefix apps/api run prisma:generate`
2. 若 `ProcessRouting.itemCode` 仍存在，使用 `psql -v ON_ERROR_STOP=1 --single-transaction` 执行 `20260812090000_process_routing_v2/migration.sql`，先迁移旧路线数据再移除旧结构。
3. 将历史 `CoreBoxMaster.cavityCount IS NULL` 的记录补为 `1`。
4. 检查 `MeltRecipeItem` 是否存在重复的 `recipeCode + itemCode`；只有重复数为 `0` 才能继续。
5. `npx prisma db push --skip-generate --accept-data-loss`。此版本唯一的数据风险提示是新增上述唯一约束，必须以前一步检查结果为前提。
6. `npm --prefix apps/api run seed:shake-clean-equipment-types`
7. `npm --prefix apps/api run backfill:shake-batches`
8. `npm --prefix apps/api run seed:final-inspection-warehouses`
9. `npm --prefix apps/api run backfill:inspection-batches`
10. `npm --prefix apps/api run backfill:work-order-melt-release -- --before=<本次版本上线前的 ISO timestamp>`

任一步骤失败时停止发布，不启动新 API。

上述步骤已使用线上发布前备份恢复到独立临时数据库，并完整演练通过；最终 `prisma migrate diff` 无差异。
