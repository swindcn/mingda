# 闽大铸件项目规划

## 项目目标

建设一套面向铸件行业的业务管理系统。当前先落地管理端，覆盖基础资料和模具开发管理；后续扩展微信小程序端，用于客户、业务员或现场人员查看进度、提交信息和处理待办。

## 应用边界

### 管理端

管理端用于公司内部人员处理日常业务，包括用户、客户、供应商、产品、模具开发、订单、生产、质检、库存、发货等流程。

### 小程序端

小程序端作为后续阶段建设目标，主要面向客户、业务员或现场协作人员。可用于查看模具开发进度、订单进度、确认图纸、提交反馈和处理待办。

### 后端服务

后端服务用于承载账号权限、业务数据、附件文件、流程状态和接口能力。当前阶段可先用 mock 数据开发管理端，待页面和业务模型稳定后再接入真实服务。

## 一期范围

一期以管理端为主，先完成以下模块：

- 登录页
- 后台布局和菜单
- 用户管理
- 客户管理
- 供应商管理
- 产品管理
- 模具开发列表
- 模具开发详情

## 后续模块

- 订单管理
- 生产计划
- 生产进度
- 质检管理
- 库存管理
- 发货管理
- 财务对账
- 数据看板
- 小程序端进度查询和待办处理

## 推荐技术方案

### 管理端

- React
- TypeScript
- Vite
- React Router
- TanStack Query
- Ant Design 或 Tailwind CSS
- lucide-react

管理端表格、筛选、表单、弹窗、上传较多，若以快速交付为目标，建议优先采用 Ant Design。

### 后端

- NestJS
- Prisma
- PostgreSQL
- JWT
- RBAC 权限模型
- 对象存储用于图纸和附件

### 小程序端

后续根据团队习惯选择：

- 原生微信小程序
- Taro
- uni-app

若需要与 React 技术栈保持一致，可优先评估 Taro。

## 开发阶段建议

1. 初始化管理端工程。
2. 接入 Figma Make 登录页和后台页面设计。
3. 建立路由、菜单、布局和 mock 数据。
4. 完成一期页面的表格、筛选、详情和状态展示。
5. 抽取共享类型到 `packages/shared`。
6. 按业务模型设计后端接口。
7. 接入真实接口和权限体系。
8. 启动小程序端规划和原型。
