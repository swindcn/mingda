# 生产工单与熔炼执行测试用例

更新时间：2026-08-26

## 基础联动

1. 生产工单的物料下拉展示物料管理中全部成品和半成品，不用 BOM、路线配置状态提前过滤。
2. 原材料、辅助材料和模具工装不能出现在生产工单物料下拉中。
3. 产品有已生效 BOM、已生效默认路线和已生效配方时可以提交工单。
4. 选择基础数据不完整的物料后，预览接口应明确提示缺少 BOM、工艺路线或熔炼配方，且禁止提交。
5. 计划件数只能为正整数。
6. 总净重、铁水需求和回料重量由后端按 BOM 计算。
7. BOM 或路线升版后，历史工单仍显示提交时锁定版本与快照。

## 排产

1. 工单提交后不立即出现在对应材质页签；手动释放熔炼后才进入对应材质页签。
2. 不同材质不能合炉。
3. 一张工单可以按整数件拆到多个炉次。
4. 一个炉次可以包含多张相同材质工单。
5. 分配件数不能超过剩余件数。
6. `t` 和 `kg` 设备能力统一转换为 kg。
7. 超过设备容量禁止生成，未满炉允许生成。
8. 配方必须已生效、材质一致且适用于目标设备。
9. 班组必须属于设备所在车间。
10. 工单产生有效分配后禁止编辑关键字段。
11. 配方三个时长必须是非负整数且合计大于 0，克隆和版本升级完整保留。
12. 历史零时长配方不能创建新炉次，并返回明确维护提示。
13. 排产车间只返回当前材质存在可用设备的启用熔炼车间；切换车间清空设备、配方和班组。
14. 后端拒绝伪造车间、其他车间设备或其他车间班组。
15. 计划开始 `08:00` 且配方时长 `60+15+15` 时，自动完成为 `09:30`；人工调整后保存调整标识。
16. 相邻时间区间不冲突；部分重叠、包含和被包含均返回冲突。
17. 首次冲突提交返回结构化 409 且不创建；确认后允许创建并写入冲突记录。

## 设备排程概览

1. 车间下所有启用且单炉容量有效的熔炼设备均返回，包括当天没有炉次的空闲设备。
2. 设备按编码稳定排序，卡片和时间线顺序一致。
3. 已撤销炉次不显示，已完成炉次可作为历史排程显示。
4. 跨日炉次按所选日期 `00:00-24:00` 裁切，相邻炉次不标冲突。
5. 重叠炉次显示冲突标识和冲突编号。
6. 历史/未来日期显示“当天有排程”，不能误标为实时生产中或显示实时倒计时。
7. 点击查询只刷新设备概览，不清除上方工单、数量和排产表单。
8. 有 `production.schedule.adjust` 权限时，待生产炉次支持拖动；其他状态或无权限时仅支持进入详情，不显示可拖动状态。
9. 没有待排工单时，待排区显示空状态，但设备排程概览仍正常显示。
10. 首次进入页面自动选择首个有效熔炼车间并加载当天排程，不要求用户先点查询。
11. 有当前或下一炉次时显示容量占比进度条，百分比等于目标重量除以单炉容量，并同时显示两项重量；超过 100% 显示红色异常状态。
12. 拖动开始时间按 15 分钟吸附，计划占用时长保持不变，预计完成时间随开始时间等量平移。
13. 炉次可跨兼容熔炉行拖动；目标炉不适用当前配方或容量不足时标记为不可放置且不提交接口。
14. 松开后显示调整确认；取消后恢复原位置，确认后刷新设备概览并显示服务端最新结果。
15. 调整后与其他炉次冲突时，首次返回冲突清单，二次确认后允许保存；相邻但不重叠的炉次不提示冲突。
16. 待生产炉次显示在计划熔炉；开始生产后改用其他熔炉时，设备卡片、冲突和甘特图必须归入实际熔炉。
17. 活动炉次超过计划完成时间后设备仍显示占用，直到炉次完成。
18. 设备排程概览遵循炉次数据范围；受限用户仍可看到授权车间设备，但不能看到无权炉次、工单编号和重量。

## 撤销和执行

1. 待生产炉次可填写原因撤销。
2. 撤销后分配件数与重量返回排产池。
3. 生产中和已完成炉次禁止撤销。
4. 待生产只能开始一次；熔炼中必须先转运，转运中才允许完成。
5. 完工实际出炉重量必须大于零。
6. 分配实际重量之和必须精确等于实际出炉重量。
7. 全部计划分配完成前，工单不能进入熔炼完成。
8. 全部有效炉次完成后进入熔炼完成，不直接进入最终完工。
9. 开始生产必须选择实际熔炉；选择计划熔炉直接开始，选择其他符合条件的熔炉必须二次确认。
10. 不同车间、不适用配方、容量不足、停用或正被其他炉次占用的熔炉禁止开始。
11. 同一炉次允许多次转运，每次必须选择同车间启用的浇注包或球化包并填写正数重量。
12. 首次转运进入转运中，后续转运保持转运中；转运明细、操作人和时间均保留。
13. 完成重量默认等于转运累计，允许人工修改；工单实际完成重量使用最终完成值分摊。
14. 工单关联炉次实时显示实际熔炉、转运累计、最终重量和关键操作人时间。
15. 待生产炉次可在详情页修改计划开始时间和兼容熔炉，后端拒绝非 15 分钟刻度、跨车间、配方不适用或容量不足的数据。
16. 调整排程提交旧 `versionNo` 时返回 409 并刷新详情；炉次已由其他终端开始、转运、完成或撤销后，旧页面不能继续调整。
17. 调整成功后产生 `SCHEDULE_ADJUSTED` 记录，包含调整前后设备、开始/完成时间和操作人。
18. 转运中的炉次存在时，关联生产工单禁止关闭。
19. 班组或熔炼车间在排产后被停用时，开始、转运和完成接口均拒绝执行。
20. 炉次实际重量偏差不直接折算工单合格件数；`meltCompletedQuantity` 按已完成炉次覆盖的分配件数计算，实际重量单独汇总，最终合格件数留给后续工序报工。

## 权限与小程序

1. 没有列表权限时不显示菜单且后端拒绝请求。
2. 创建、编辑、关闭、排产、撤销、开始、转运和完成是独立权限。
3. 调整排程除 `production.schedule.adjust` 外还必须通过炉次数据范围校验，不可见炉次返回 404 且不得发生任何更新。
4. 执行班组成员可在小程序查看对应炉次。
5. 非执行班组成员即使有相同菜单和按钮权限，也不能查看或操作炉次。
6. 小程序列表支持下拉刷新。
7. 小程序操作成功后重新读取接口，不使用本地假成功。
8. 小程序扫码炉号或包号后，只能匹配执行选项接口返回的设备；未知二维码禁止提交。
9. 小程序列表和详情显示计划开始时间，不再使用兼容字段 `plannedOutputAt` 作为“计划出炉”。
10. `production.schedule.adjust` 为管理端权限，不出现在小程序权限树；小程序只展示服务端调整后的最新计划时间和设备。

## 工单工艺路线执行入口

### 工序摘要与关联

1. 工单详情读取的是工单提交时锁定的工艺路线版本；后续路线停用或升版不改变历史工单的节点、前后关系和执行范围。
2. 路线表格每个节点显示工序状态、工序进度、实际设备、实际班组和操作列；未创建任务时设备/班组显示 `-`，不得显示路线配置中的适用设备。
3. 制芯按有效任务覆盖数显示待下达、部分下达或已下达；已取消任务保留历史查看，但不计入有效覆盖数、完成数量、设备或班组汇总。
4. 一个工单分配多个炉次时，熔炼节点正确汇总各有效炉次的件数、状态、实际设备和班组；已取消炉次不计入活动汇总，但节点仍显示曾经已下达且进度为已取消。
5. 造型任务状态从待派工、待生产、生产中到已完成的映射正确；浇注、落砂清理、终检队列未生成时显示等待上游，生成后显示查看任务。
6. 落砂和清理在路线中只占一个节点，摘要同时展示内部两个阶段的真实进度；未接入的自定义工序显示暂未接入，不出现可执行按钮。

### 手动释放熔炼

1. 新建生产工单后不出现在合炉排产池，工单详情熔炼节点为待下达。
2. 在工单详情点击“下达熔炼”后进入合炉排产池，但只释放工单，不自动生成炉次；重复点击/重试只返回已释放结果。
3. 制芯未完成或存在待烘干砂芯时，接口返回具体软提示；用户确认后仍可释放，后端不硬拦截。
4. 熔炼释放成功后保存释放时间和操作人，刷新详情和排产池仍保持一致；生产工单关闭后释放接口拒绝执行。
5. 只有 `production.schedule.release` 时可以释放熔炼，没有该权限时不显示按钮且直接调用接口返回 403；拥有 `production.schedule.create` 不应自动获得释放权限。
6. 没有 `production.work_order.view` 或工单数据范围不可见时，不能读取路线摘要，也不能通过释放接口越权改变工单。

### 多任务跳转与 `workOrderId`

1. 从路线节点查看制芯、熔炼、造型、浇注、落砂清理或终检任务时，目标列表携带 `workOrderId` 并只返回该工单数据。
2. 后端在数据库查询条件中应用 `workOrderId`，同时叠加用户数据范围；不能依赖前端二次过滤。
3. 从第 2 页或带关键词/状态的任务列表进入详情再返回，工单筛选、状态、关键词和分页上下文保持不变。
4. 旧页面打开期间，移动端或其他管理端改变任务状态后，点击下达/查看应重新取服务端状态；提交旧版本时返回 409，并刷新而不是覆盖新数据。

### 并发、取消与回填

1. 两个管理端同时释放同一工单时只能有一个有效写入，最终只有一个释放时间/操作人结果，排产池不重复出现数据。
2. 网络重试同一个释放请求不新增记录、不重复审计、不改变已保存的操作人和释放时间。
3. 已取消制芯任务或熔炼炉次仍能从路线节点查看历史；取消数据不计入当前有效数量和活动设备汇总，不能被摘要误判为全部完成。
4. 历史工单回填使用 `--before=<ISO timestamp>`；缺少截止时间、日期非法或参数为空时命令失败，不执行全量回填。
5. 回填仅处理 `meltReleasedAt IS NULL AND createdAt < cutoff` 的工单；在相同截止时间重复执行结果幂等，新建工单不会被释放。
6. 迁移/回填后验证：历史工单按截止时间可进入排产池，新建工单仍需手动释放；数据库字段、索引、外键和权限默认值均存在。

## 合型浇注

1. 造型有效报工的合格箱数生成待浇砂型批次；造型废品和零数量关闭不生成。
2. 待浇批次沿工单锁定路线真实边找到首个可达浇注汇合点；无可达节点时造型报工仍成功但不生成待浇批次。
3. 待浇队列按造型任务聚合，具体扣减按最早合型时间和批次 ID 固定 FIFO，可跨多笔造型报工。
4. 铁水包次必须来自包含当前工单分配、材质一致且状态为转运中或已完成的炉次，转运设备必须为启用的浇注包或球化包。
5. 浇注工位只能选择工单锁定路线中浇注节点绑定且启用的设备；未配置时明确提示维护工艺路线。
6. 理论重量等于浇注总箱数乘模具穴数乘单件浇注毛重；实际重量默认理论值并允许修改。
7. 实际重量超过包次余额时检查接口返回 `TRANSFER_OVERDRAW`，未确认返回 409，确认后允许保存负余额。
8. 合型停留不足 90 分钟为正常，90 至 120 分钟为预警，超过 120 分钟返回 `CRITICAL_HOLD` 并要求单人二次确认。
9. 浇注废品大于零时必须选择绑定当前浇注工序的缺陷，缺陷数量合计等于废品箱数。
10. 相同任务和 `requestId` 重试不重复扣减；包次旧 `versionNo` 返回 409，管理端和小程序提示刷新重试。
11. 管理端撤销浇注报工后，原砂型批次余量精确恢复，包次余额按有效报工重新计算；小程序不提供撤销。
12. 造型报工已有有效浇注消费时禁止撤销，必须先撤销浇注报工。
13. 造型任务完成且全部待浇余量为零时浇注节点完成；队列清空但造型仍生产时显示等待后续造型。
14. 管理端 `view/report/reverse` 和小程序 `view/report` 独立授权，菜单、按钮和 API 均按实际权限生效。

## 落砂清理

1. 有效浇注报工 `3` 箱、任务穴数快照 `2` 时生成 `6` 件待落砂；浇注废品不计入。
2. 浇注到落砂节点沿工单锁定路线真实边查找；历史路线停用不影响执行，无可达节点时浇注仍成功但不生成批次。
3. 同一浇注报工最多生成一个待落砂批次；历史补建重复运行不产生重复数据。
4. 落砂 FIFO 按 `pouredAt -> id`，清理 FIFO 按 `availableAt -> id`；一次报工可跨批次且消费明细合计准确。
5. 上游浇注报工已有有效落砂消费时禁止撤销；落砂报工已有有效清理消费时禁止撤销；清理已有下游消费时禁止撤销。
6. 冷却时长未到时检查接口返回提醒，未确认拒绝提交，确认后允许并记录要求分钟、实际分钟和提前落砂标志。
7. 冷却时长达到后无需二次确认；路线后续升版或停用不改变历史批次冷却快照。
8. 落砂设备必须启用、绑定当前路线节点且设备类型为“落砂”；清理设备类型仅接受“清理、抛丸、打磨、切割”。
9. 两阶段废品大于零时，只能选择绑定 `OP-SHAKE` 的启用缺陷，缺陷数量合计等于废品数；其他工序缺陷应被拒绝。
10. 清理报工生成等量有效 `BlankOutputBatch`；清理废品不能计入合格毛坯。
11. 当前节点没有后继时毛坯状态为 `WAITING_WAREHOUSE`；一个后继时记录 `nextRoutingNodeId`；多个直接后继时拒绝报工。
12. 当前落砂、清理队列为空但上游浇注未结束时任务状态为 `WAITING_POURING`；上游结束且两队列均清零时为 `COMPLETED`。
13. 同一任务重复提交相同 `requestId` 不重复扣减或产出；提交旧落砂或清理批次 `versionNo` 返回 `409` 且数量不变化。
14. 独立补建命令与报工并发时保持一致结果；报工和撤销先锁任务再锁 FIFO 批次，不允许更晚批次越过更早历史批次被消费。
15. 有可达落砂节点的浇注报工解析为 `CREATED`；已有批次但状态仍为 `PENDING` 时只修复状态，不重复创建。
16. 无可达落砂节点、已撤销或无有效合格数的报工解析为 `NOT_APPLICABLE`，不再被详情/报工误判为补建缺口，重跑不重复解析。
17. 新库设备类型初始化写入完整默认数组；已有记录只追加落砂、清理、抛丸、打磨、切割，保留自定义项且不恢复用户删除的其他默认项。
15. 正常列表查询不创建历史批次；历史缺口由部署命令逐页独立提交，超过 1000 条可全部完成，中断重跑不重复。
15. 管理端列表使用后端分页、固定操作列和真实冷却状态；详情包含任务、落砂报工、清理报工、批次追溯四类信息。
16. 小程序首页入口受 `mini.production.shake_clean.view` 控制，报工按钮只依赖服务端 `allowedActions`，无动作权限时直接访问页面也不能提交。
17. 小程序列表使用稳定 cursor、下拉刷新和加载更多，追加时按任务 ID 去重；筛选或数据变化不能产生重复记录。
18. 小程序落砂和清理均支持设备选择/扫码防错、快捷数量、缺陷录入；清理额外记录浇冒口重量，不提供撤销。
19. 普通用户列表和详情必须遵循 `production:molding_tasks` 数据范围；只有查看权限时不得获得报工或撤销动作。
20. 修改小程序 `src` 后执行全量构建，确认 `dist/pages/shake-clean/` 与源码同步且 WXSS 无非法字符。

## 成品终检与清理返修

1. 清理合格批次的锁定路线下一节点为 `OP-INSP` 时生成一条待检批次；重复解析不重复创建，其他下一节点不进入终检。
2. 历史路线已停用但工单锁定版本包含终检时仍可报工。
3. 待检批次按 `availableAt -> id` FIFO 消费，一次报工跨批次时消费明细与余量准确。
4. 合格、返修、报废合计为零或超过剩余待检数时拒绝；等于剩余数时允许提交。
5. 合格数生成等量毛坯入库单、库存批次和入库流水；刷新后数据仍存在。
6. 报废重量留空时按报废件数乘工单净重计算；填写实际重量时保存实际值并更新回炉料余额。
7. 返修任务只能选择锁定路线清理节点绑定且启用的清理设备；返修合格数重新进入待检队列。
8. 终检缺陷只能选择绑定 `OP-INSP` 的启用缺陷；缺陷数量不能超过返修与报废数量；图片最多一张。
9. 相同 `requestId` 重试不重复扣减、入库或记账；旧批次/任务版本返回 `409` 且余额不变。
10. 无下游消费时管理端可撤销并恢复待检、毛坯库存和回炉料余额；小程序无撤销入口。
11. 返修已报工或毛坯已出库时禁止撤销原终检报告。
12. 待检或返修仍有余量时工单不能完成；全部清零且上游结束时，完成数等于有效毛坯入库数。
13. 只有 `view` 权限时可查看但无报工/撤销按钮；直接调用动作接口返回 403。
14. 管理端列表支持查询、状态页签、列宽拖动和固定操作列；小程序支持扫码、下拉刷新、分页和权限入口。
