## 页面与交互标准

### 二级页面返回样式

二级页面统一使用：

```text
apps/admin/src/components/SubPageHeader.tsx
```

标准样式：

- 左侧为返回箭头图标按钮
- 右侧为页面标题
- 可选副标题
- 可选右侧操作按钮

不要再使用“返回”文字按钮样式。

已使用页面：

- 部门同步配置帮助
- 模具开发详情

### 表格操作列标准

表格数据列允许左右滚动，操作列固定在右侧。

操作列要求：

- 操作列固定右侧：`fixed: 'right'`
- 数据列横向滚动：`scroll={{ x: ... }}`
- 表格使用 `tableLayout="fixed"` 时，长文本列需要 `ellipsis`
- 操作按钮不换行
- 操作按钮尽量使用短词或图标，避免过长
- 操作超过 3 个时，只展示前 3 个，从第 4 个开始放到“更多”下拉菜单
- 操作数量应按“当前登录用户实际有权限看到的操作”计算；如果授权后只剩 2 个操作，不应显示“更多”
- 该规则适用于所有菜单/业务列表，不只角色权限页
- 固定操作列宽度要给足，不要让按钮挤出列外；目前三段紧凑操作建议宽度约 210px
- 直显按钮文本应使用短词，例如“权限”“用户”“修改”，完整语义放在更多菜单或 tooltip 中

通用组件：

```text
apps/admin/src/components/TableActions.tsx
```

用法要求：

- `label` 用于完整语义，通常显示在更多菜单中
- `shortLabel` 用于表格直显短词
- `visibleCount` 默认值为 3，特殊窄列场景才单独调整
- 删除等危险操作需要二次确认，当前推荐使用 `Modal.confirm`

### 表格列宽拖拽标准

数据列表需要支持拖动调整列宽。统一使用：

```text
apps/admin/src/components/ResizableTable.tsx
```

要求：

- 通过表头右侧拖拽手柄调整列宽
- 使用 `storageKey` 将用户调整后的列宽保存到 `localStorage`
- 继续兼容固定右侧操作列
- 继续兼容横向滚动
- 后续新增业务列表优先使用 `ResizableTable`，不要直接使用 Ant Design `Table`

当前已接入：

- 角色权限列表
- 用户管理列表
- 部门管理列表
- 客户管理列表
- 供应商管理列表
- 产品管理列表
- 模具开发列表

当前主业务列表已优先采用该标准。弹窗内的小型内嵌表格可按复杂度决定是否迁移。

### 上传图片标准

开发下达页的图纸/图片上传要求：

- 上传后展示方形缩略图
- 缩略图从左到右横向排列
- 点击缩略图可预览大图

当前使用 Ant Design `Upload` 的 `picture-card` 样式和 `Image` 预览。

### 布局滚动标准

后台布局采用：

- 外层 `Layout` 高度为 `100vh`
- 左侧菜单 `Sider` 独立滚动
- 主内容 `Content` 独立滚动

不要依赖 `body` 滚动。`body` 当前是 `overflow: hidden`。

相关文件：

```text
apps/admin/src/layouts/AppLayout.tsx
apps/admin/src/index.css
```

## 部门管理业务规则

部门管理目的不仅是组织展示，还用于未来角色数据权限。

- 树形部门

- 编辑部门
- 删除部门

第三方同步来源：

- 钉钉
- 企业微信

同步配置字段：

- 钉钉：AppKey / AppID、AppSecret

### 模具开发详情

详情页采用截图参考交互：

- 左侧：开发信息、模具图片
- 右侧：开发进度流程时间轴

要求：

- 未达到的流程只显示节点标题
- 已提交的流程显示具体内容
- 不展示“小程序动作”字段
- 支持编辑开发需求

当前流程节点：

- 开发下达
- 供应商确认
- 供应商发货
- 收货确认

提交后才显示在时间线的记录：

- 试模记录
- 量产记录
- 模具评判记录
- 开发中止记录

流程动作要求：

- 供应商确认节点右侧显示“图纸确认”按钮；确认弹窗文案为“是否确认图纸”；确认后记录确认人、确认时间，并推进到下一节点。
- 供应商发货节点右侧显示“发货”按钮；发货弹窗需填写快递单号并上传发货图片，图片最多 3 张且至少 1 张；确认后记录发货人、发货时间、快递单号、发货图片，并推进到下一节点。
- 收货确认节点右侧显示“收货”按钮；收货弹窗需上传收货图片，图片最多 3 张且至少 1 张；确认后记录收货人、收货时间、收货图片，并推进到下一节点。
- 收货完成后，详情页“开发进度流程”标题右侧显示三个按钮：试模生成、批量生产、模具评判。
- 试模生成和批量生产都可多次提交，每次记录都保留在开发进度里。
- 时间线记录按提交次数独立显示，例如“试模记录（一次）”“试模记录（二次）”“量产记录（一次）”。
- 试模生成和批量生产每次提交都需要填写人、拍摄产品图片、破坏性检测图片；两类图片都至少 1 张。
- 模具评判需要填写评判人、评判结果（通过 / 不通过）、是否开发完成（是 / 否，默认是）、评判理由。
- 收货后即可进行试模生成、批量生产、模具评判；三者不强制互相前置。
- 试模生成、批量生产、模具评判、中止开发不作为固定开发流程节点；只有提交数据后才作为记录显示到时间线上。
- 模具评判提交且“是否开发完成”为是后，本单状态为已完成，不再强制要求至少一次试模生成或批量生产。
- 详情页右上角提供“中止开发”按钮；填写中止理由后，保留已有执行过程数据，并将本单状态标识为已中止。
- 开发中止后，不能再提交试模生成、批量生产数据，也不提供收货/发货/图纸确认等推进按钮。
- 模具评判完成后，不能再提交试模生成、批量生产数据，也不能中止开发；相关按钮隐藏。

## 开发注意事项

- 不要把 Figma Make 代码直接照搬进项目，应转换为当前 Ant Design 风格。
- 不要新增无必要的图标库，当前已有 Ant Design Icons 和 lucide-react。
- 管理端偏业务系统，应保持信息密度，不做营销页风格。
- 表单、表格、弹窗优先使用 Ant Design。
- 涉及列表操作，先考虑是否需要固定操作列和 `TableActions`。
- 涉及二级详情页，使用 `SubPageHeader`。
- 涉及权限、数据归属、同步规则时，应优先维护本文档。
